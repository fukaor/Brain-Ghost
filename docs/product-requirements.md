## プロダクト概要

### 名称
**Brain Boost**（仮）— ミニゲーム詰め合わせ型の脳トレアプリ

- キャッチコピー: **「毎日2分、昨日の自分に挑め」**
- ストア掲載コピー候補: 「『いつもの自分』と毎日対戦。友達と同じ問題で脳トレ対決。」

### プロダクトコンセプト

- **毎日2分で完結する脳トレ**: 1プレイ=3種×30秒=約2分。通勤の信号待ちレベルで1日のルーティンが完結する
- **ゴースト対戦（独自要素 1）**: 「いつもの自分」（直近5回の平均）と毎プレイ対戦。成長を物語として可視化する
- **デイリーチャレンジ共通化（独自要素 2）**: 日付シードで全ユーザー同じ問題を出題（Wordle方式）。スコアをURLで共有し、友達と同じ問題で対決できる
- **ゴースト生霊キャラクタ（独自要素 3）**: ゴースト対戦のデータをユーザ自身の **生霊キャラクタ** として全画面に登場させ、対話式に案内する。精度 % → 現出度（不透明度）、脳年齢 → 見た目年齢、ストリーク → オーラと連動し、"昨日の自分" が文字通り横に立つ鏡体験を提供（詳細: GDD §5e / FR-14）

### プロダクトビジョン

脳トレを「毎日やる理由がある体験」にする。既存の脳トレアプリは「脳年齢が出る、ただそれだけ」で離脱される。Brain Boostは**ゴースト対戦**で「昨日の自分に勝った」という物語を毎日作り、**デイリーチャレンジ共通化＋シェアURL**で友達との比較をバイラル装置に変える。通勤電車の2分と、Xでの10秒のシェアで、脳トレが「エンタメ」として定着する世界を作る。

### 目的

- 既存脳トレアプリの「毎日やる動機の弱さ」を、ゴースト対戦という独自要素で解決する
- Web版とAndroid版を同時リリースし、Web版でバイラル拡散を、Android版でマネタイズを担う
- 個人開発者（ねこぽ/ReigalLabs）が1ヶ月のMVP開発で市場投入できるスコープに収める
- Android版の広告非表示買い切り課金（¥300〜500）で、継続率の高いロイヤルユーザーから初日から収益化する
- 脳トレを「医学的効果を謳わないエンターテインメント」として提供し、表現上のリスクを避ける

### 戦略: 「パクリ＆改善」

ブルーオーシャンは狙わない。既存競合7本（みんなの脳トレ、毎日脳トレ、PEAK、他）の競合調査から、**証明済みの型をパクり、口コミで繰り返し指摘される不満を丁寧に潰す**方針を取る。詳細は GDD §1 / 付録A・B を参照。

## ターゲットユーザー

年齢・性別ではなく**動機**でペルソナを定義する。2つのペルソナは独立したセグメントではなく、「ペルソナ2が広め、ペルソナ1が定着する」という関係で設計する。

### プライマリーペルソナ: セルフチャレンジャー（自己改善型）

**DAU と収益の主軸**。設計判断で迷ったらこちらを優先する。

| 項目 | 内容 |
|------|------|
| **代表例** | 30代会社員。男女問わず。Wordleの代わりに毎朝の通勤電車でやる |
| **動機** | 自分の成長を数字で実感したい。昨日の自分より良くなりたい |
| **利用シーン** | 通勤電車の中（毎朝のルーティン）。帰りの電車でリベンジすることもある |
| **刺さる機能** | ゴースト対戦、スコア前回比、ベスト更新、レーダーチャートの弱点導線 |
| **行動パターン** | 毎日欠かさずデイリーをやる。ストリークを大事にする。シェアは頻繁にしない |
| **離脱リスク** | スコア停滞（2〜3週間目）で成長実感がなくなる |
| **対策** | 難易度の動的調整、弱点導線、直近5回平均ゴーストが停滞期でも接戦を演出 |
| **マネタイズ特性** | 広告非表示買い切り課金の主要ターゲット。リワード広告も積極的に視聴 |

### セカンダリーペルソナ: ライトコンペティター（社交型）

**バイラル拡散の手段**。このペルソナのためにプライマリーの体験を犠牲にしない。

| 項目 | 内容 |
|------|------|
| **代表例** | 25歳。Xのねこぽの投稿でシェアURLを見て流入 |
| **動機** | 友達やフォロワーとライトに競いたい。結果を見せたい |
| **利用シーン** | 友達/フォロワーがシェアしたURLから流入。「勝てる？」で始める |
| **刺さる機能** | デイリーシード共通化、シェアURL、OGPカード |
| **行動パターン** | 毎日はやらない。シェアされたときだけプレイ。結果は必ずシェアする |
| **離脱リスク** | 周囲が飽きてシェアが減る（1〜2週間目） |
| **対策** | Web版で参入障壁ゼロ、新ゲーム追加で精度低下→再流入フック |
| **マネタイズ特性** | 広告は気にならない（接触頻度が低い）。課金率は低い |

### ペルソナが設計に与える影響

| 判断 | プライマリー要求 | セカンダリー要求 | 採用方針 |
|---|---|---|---|
| 結果画面の優先順位 | スコア前回比 → ゴースト勝敗 → 脳年齢 | スコア絶対値 → シェアボタン | 「サマリー＋スクロールで詳細」の2層構成。スコア前回比を最上部、シェアボタンを常時表示 |
| ゴースト表示 | 毎日見るので控えめで良い | 初回でインパクトが必要 | プレイ中はプログレスバー小、結果画面で勝敗を大きく演出 |
| シェア画像 | あまり使わない | 最重要。映えないとシェアしない | OGPカードデザインに工数をかける |
| 色使い | スコア上昇=緑/青で成長実感 | 勝敗の色分け | ポジティブ色を基調。**負けても赤は使わない**（勝ち=緑/金、負け=グレー） |
| 情報密度 | 詳細データを見たい | シンプルで良い | 2層構成で両立 |

- **地域**: 日本国内
- **将来**: v2.0 で英語対応（ゲームが言語非依存なのでローカライズコストは低い）

## 機能要件

### コア機能 (MVP)

#### FR-01: ミニゲーム 6種

**ユーザーストーリー**:
セルフチャレンジャーとして、毎日2分で完結する多様な脳トレ体験のために、6種類のミニゲームをプレイしたい。

**含まれるゲーム**:
1. **反射タップ** — 反応速度。ランダム位置に出現するターゲットを20回タップし平均反応時間を計測
2. **フラッシュ暗算** — 計算力。次々表示される数字の合計を30秒で答える
3. **数字さがし** — 観察力。1〜25の数字をランダム配置から昇順にタップ（クリアタイム評価）
4. **ストループ** — 注意力・判断力。「赤」と青で書かれた文字の「色」を答える。30秒間に何問正解できるか
5. **順番記憶** — 短期記憶力。N個のパネルが順番に光り、同じ順番でタップ（N+1に挑戦し続ける）
6. **神経衰弱ライト** — 記憶力・観察力。4×4のカードでペアを探す

**受け入れ条件**:
- [ ] 6種すべてが30秒〜1分で1ゲーム完結する
- [ ] 6種すべてが**パラメトリック生成**で毎回問題が変わる（固定パターンは禁止）
- [ ] 6種すべてが**言語非依存**（知識問題・語彙問題を含まない）
- [ ] 操作は**タップのみ**（マルチタッチ・スワイプは使わない）
- [ ] 各ゲームにルール説明画面＋「3...2...1...」カウントダウンが入る
- [ ] 2回目以降のプレイではルール説明をスキップできる
- [ ] 各ゲームは日付シード（`YYYYMMDD` 整数）を受け取ると全ユーザー共通の問題を生成できる

**優先度**: P0(必須)

**詳細仕様**: GDD §4 各ゲームセクション参照

#### FR-02: ゴースト対戦システム

**ユーザーストーリー**:
セルフチャレンジャーとして、自分の成長を物語として実感するために、「いつもの自分」（直近5回平均）と毎プレイ対戦したい。

**ゲーム分類**（ゴーストUI の振る舞いに直結する）:

以下の判別基準でミニゲームを2種類に分類する。

| 分類 | 判別基準 | 対象ゲーム | プレイ中のゴースト表示 |
|---|---|---|---|
| **タイム系** | 制限時間（30秒）内にカウントアップする正答数を競う。時間はカウントダウン | 反射タップ / フラッシュ暗算 / ストループ | プログレスバー2本（自分 vs いつもの自分） |
| **クリア系** | 目的達成（全パネル/全カード/全数字）までの所要時間・タップ数を競う。時間はカウントアップ | 順番記憶 / 神経衰弱 / 数字さがし | **非表示**（操作に集中させるため）。結果画面でのみタイム比較 |

**数字さがしの扱い**: 数字さがしは「1〜25 を昇順にタップするクリアタイム型」であり、プレイ中にリアルタイムの目標達成状況が変化する。ゴーストバーを表示することは技術的には可能だが、短時間での集中操作を妨げないよう**クリア系として扱い、プレイ中のゴーストは非表示**とする（GDD §5b の設計意図に従う）。

**解放モデル（2段階）**:
ゴースト対戦は**機能解放**と**ゲーム別データ成立**の2段階で扱う。

| 段階 | 条件 | 状態 |
|---|---|---|
| **第1段階: 機能解放** | 精度100%（全6種を1回以上プレイ）→ FR-05 と連動 | ゴースト対戦機能が「有効」になる。UI上のロックアイコンが外れる |
| **第2段階: ゲーム別データ成立** | 該当ゲームを**5回**プレイしてプレイログが蓄積される | そのゲーム個別に「いつもの自分」が生成され、プログレスバー/結果比較が表示される |

全6種を1回ずつやった直後は、機能は解放されているが各ゲームのログが1回分しかないため、まだゴースト表示は出ない。2回目以降で徐々にデータが蓄積され、**5回目以降に正式なゴースト対戦**（直近5回平均）が成立する。

**受け入れ条件**:
- [ ] 各ミニゲームのプレイログ（タイムスタンプ付き正答イベント列）がローカルに保存される
- [ ] ゴーストデータは**直近5回のプレイ平均**を「いつもの自分」として表示する
- [ ] **精度100%に到達するまで**は、ゴースト対戦機能自体がロック状態（🔒 表示）
- [ ] **精度100%到達後**も、プレイ回数が **5回未満のゲーム**ではそのゲームのゴーストは表示されず、「あと○回であなたのゴーストが生まれます」のような育成メッセージを出す
- [ ] **該当ゲームのプレイ回数 ≥ 5 回**になったら、そのゲームのゴースト対戦が正式に成立する
- [ ] **タイム系ゲーム**（反射タップ・フラッシュ暗算・ストループ）ではプレイ中に画面下部にプログレスバー2本（自分 vs いつもの自分）を表示する
- [ ] **クリア系ゲーム**（順番記憶・神経衰弱・数字さがし）ではプレイ中ゴースト非表示、結果画面でタイム比較を表示する
- [ ] ゴースト勝敗の表示は勝ち=緑/金、負け=グレー。**赤は使わない**
- [ ] ベスト記録は別枠で常時表示する（ゴースト解放状態に依存しない）
- [ ] 新ゲーム追加時（v1.1 以降）は、その新ゲームのプレイ回数が 5 未満の間だけそのゲームのゴーストが非表示になる（既存ゲームのゴーストには影響しない）

**優先度**: P0(必須)

**詳細仕様**: GDD §5b 参照

**ビジュアル表現層**: データ層（本要件）に加え、ゴーストを視覚・対話層として全画面で演出する **FR-14「ゴースト生霊キャラクタ」** と連動する。プレイ中の非表示ルールは本要件（FR-02）、キャラクタとしての登場・セリフは FR-14 が担う。

#### FR-03: デイリーチャレンジ（全ユーザー共通問題）

**ユーザーストーリー**:
ライトコンペティターとして、友達と同じ問題でスコアを比較するために、全ユーザー共通のデイリーチャレンジをプレイしたい。

**選出アルゴリズム**:
- 日付シード（`YYYYMMDD` の 8 桁整数）で初期化した `RandomNumberGenerator` を使って、`ALL_GAMES` 配列（6種）を Fisher-Yates シャッフルし、先頭 3 種を取り出す
- 偏り抑止・同一ゲーム連続禁止などの追加制約は MVP では設けない（RNG 分散に委ねる）
- 実装の詳細は `docs/functional-design.md` の DailySeed コンポーネントを参照

**受け入れ条件**:
- [ ] 日付（`YYYYMMDD`）をシードにした `RandomNumberGenerator` で、**6種から3種のゲームを選出**する（同じ日付なら全ユーザー同一の3種）
- [ ] 選出には Fisher-Yates シャッフルを使い、`Array.shuffle()`（グローバル乱数を使用）は使わない
- [ ] 選ばれた各ゲームの問題も日付シードで生成する（全ユーザー同一の問題）
- [ ] ホーム画面に「今日のチャレンジ」として3種セットが表示される
- [ ] 3種を通しでプレイし、完了後に総合結果画面に遷移する
- [ ] デイリーチャレンジと自由選択モードは別枠（自由選択はランダムシード）
- [ ] 日付はローカルタイム基準（UTC+9 固定）で判定する
- [ ] その日のチャレンジを一度完了しても、もう一度挑戦できる（記録は初回のみ正式扱い）

**優先度**: P0(必須)

**詳細仕様**: GDD §5c 参照

#### FR-04: スコアリング・脳年齢・レーダーチャート

**ユーザーストーリー**:
セルフチャレンジャーとして、自分の能力を多角的に把握するために、スコア・脳年齢・6能力レーダーチャートで結果を可視化してほしい。

**基準年齢の扱い**:
脳年齢の算出には基準年齢が必要だが、**オンボーディングでの年齢入力は行わない**（2分完結の思想を守るため）。代わりに以下の方針を採る:

- 初回は**基準年齢 30歳**（日本の脳トレアプリ主要ユーザー層の中央値想定）を使ってスコア→脳年齢の換算を行う
- 設定画面で**年代を任意変更**できる（10代 / 20代 / 30代 / 40代 / 50代以上 の 5 段階選択）
- 設定を変更すると以降の脳年齢表示に反映される（過去の脳年齢履歴は表示時点の設定値で再計算）
- 年代未設定のユーザーに対して、ホーム画面で**一度だけ**「年代を設定するとより正確になります」の任意バナーを表示（拒否可能）

**脳年齢算出アルゴリズムの要点**（詳細は `docs/functional-design.md` A-02）:

| 年代 | 中央年齢（基準年齢） |
|---|---|
| 10s | 15歳 |
| 20s | 25歳 |
| 30s（デフォルト） | 30歳 |
| 40s | 45歳 |
| 50s+ | 55歳 |

- **初回補正**: 合計スコアに基づく脳年齢から、**ランダムに 3〜5 歳**若返らせる（毎プレイではなく初回プレイ1回のみ、`RandomNumberGenerator` で 3/4/5 歳のいずれか）
- **上限キャップ**: 脳年齢は **中央年齢 + 10歳** を超えない
- **下限クランプ**: 脳年齢は **中央年齢 − 15歳** を下回らない（非現実的な値の抑止と、上限との対称性維持）
- **絶対下限**: 10歳（10代ユーザーの境界ケースでも 10 歳未満にならない）

**受け入れ条件**:
- [ ] 6ゲーム各自の計算式でスコアを算出する（GDD §6 スコア算出表、`docs/functional-design.md` A-01）
- [ ] 合計スコアを「脳年齢」に翻訳して表示する
- [ ] **基準年齢 30歳**をデフォルトとし、初回オンボーディングで年齢入力は求めない
- [ ] 設定画面で年代（10代 / 20代 / 30代 / 40代 / 50代以上）を任意変更できる
- [ ] 初回プレイ時は脳年齢から**ランダムに 3/4/5 歳のいずれかを減算**して表示する（甘め補正）
- [ ] 脳年齢は選択年代の **中央年齢 + 10歳** を超えないキャップを持つ
- [ ] 脳年齢は選択年代の **中央年齢 − 15歳** を下回らない下限クランプを持つ
- [ ] 脳年齢表示の絶対下限は **10歳**
- [ ] 6つの**能力軸**（計算力・記憶力・注意力・反射速度・観察力・判断力）でレーダーチャートを描画する
- [ ] **能力軸は6つで固定**。ゲームが増えても軸は増やさない（新ゲームは既存軸にマッピング）
- [ ] 脳年齢表示に「**エンターテインメント目的**」の注記を必ず添える（医学的効果は謳わない）
- [ ] 弱い能力から該当ゲームに直接飛べる「[鍛える]」ボタンを表示する

**優先度**: P0(必須)

**詳細仕様**: GDD §6、§10b のマッピング表、`docs/functional-design.md` A-02

#### FR-05: 精度システム（未プレイゲームによる測定精度低下）

**ユーザーストーリー**:
セルフチャレンジャーとして、途中離脱しても進捗が無駄にならないために、プレイした種目数に応じた暫定脳年齢を見たい。

**受け入れ条件**:
- [ ] `精度 = プレイ済み種目数 / 全種目数 × 100%` で計算する
- [ ] 1種でも脳年齢が出る（暫定表示）
- [ ] 精度100%（全種プレイ済）になると、以下が解放される:
  - **ゴースト対戦機能の有効化**（第1段階。各ゲームの実際のゴースト表示は FR-02 の第2段階＝5回蓄積を満たして初めて出る）
  - 能力レーダーチャート
  - 正式脳年齢（「約○○歳」→「○○歳（確定）」）
- [ ] 精度はパーセント表示（ゲーム数に依存しない）
- [ ] 未解放機能はロックアイコン🔒とともに「精度100%で解放」と表示する
- [ ] 新ゲーム追加時は精度が自動的に下がる（例: 6/9=67%）→ 新ゲームプレイの動機になる
- [ ] **精度の計算対象は「1回以上プレイしたかどうか」**であり、ゴースト対戦の5回蓄積とは独立した指標である

**優先度**: P0(必須)

**詳細仕様**: GDD §5「精度の表示」セクション、および本PRDの FR-02「解放モデル」を参照

#### FR-06: 初回オンボーディング

**ユーザーストーリー**:
初めてアプリを開くユーザーとして、アプリの価値をすぐ理解するために、最短30秒で1種目完了できる脳力測定体験から始めたい。

**受け入れ条件**:
- [ ] アプリ初回起動時に「あなたの脳力を測定します」イントロ（2秒）が表示される
- [ ] **年齢入力や会員登録などのステップを挟まない**（脳年齢の基準年齢 30歳 は FR-04 の方針に従う）
- [ ] 最初のゲームは**反射タップ**（説明不要レベルの直感的なゲーム）
- [ ] ゲーム順序は直感的理解の順: 反射タップ → フラッシュ暗算 → 数字さがし → ストループ → 順番記憶 → 神経衰弱
- [ ] 1種終わるたびに「続ける（残り○種）」or「ここまでの結果を見る」を選べる

- [ ] 初回フロー中のルール説明（各ゲームの1回目）は省略せず、カウントダウン付きで表示される
- [ ] **2回目以降（同一ゲームの再プレイ、または `onboardingCompleted == true` 後の再ホーム）**では [スキップ] ボタンが出る（FR-07 と整合）

#### FR-09: ストリーク・ハンコ制度（継続モチベーション）

**ユーザーストーリー**:
セルフチャレンジャーとして、毎日続ける動機のために、ストリークとハンコで継続を可視化したい。

**ストリークの定義と空白日の扱い**:
「ストリーク」は**1回以上プレイした日の連続カウント**として定義する。空白日が出た場合の挙動は以下の通り:

| 直近プレイからの経過日数 | 再開時のストリーク挙動 |
|---|---|
| **0日**（同日再プレイ） | ストリークは変動なし |
| **1日**（翌日プレイ） | ストリーク +1 |
| **2〜7日の空白** | ストリークは**維持**される（空白日数は加算されない）。再開日から +1 される。ホームに「おかえりなさい！ストリーク ○日 継続中」の復帰演出を1回表示 |
| **8日以上の空白** | ストリークは**リセット**され、再開日から 1 日目として再カウントされる |

**設計意図**: 既存アプリの「1日休んだだけでゼロリセット → やる気半減」という最大の不満を回避するため、7日までは「日常の忙しさ」として許容する。ただし8日以上空くと完全に習慣化が途切れているためリセットする（だらだらと無限に維持されると達成感が薄れる）。

**受け入れ条件**:
- [ ] プレイした日ごとにハンコが押される（カレンダーUI）
- [ ] 連続プレイ日数（ストリーク）をホーム画面に表示する
- [ ] ストリークは「1回以上プレイした日」の連続カウントで定義する
- [ ] 直近プレイから **2〜7日の空白**はストリークが維持される（空白日数は加算されない）
- [ ] 直近プレイから **8日以上の空白**はストリークがリセットされる
- [ ] 2〜7日の空白後に再開した場合、ホームに「おかえりなさい！ストリーク ○日 継続中」の復帰演出を1回表示する
- [ ] ストリークリセット時にネガティブな演出や赤色・警告音を使わない（ペルソナ1のモチベーションを守る）
- [ ] 日付判定はローカルタイム（UTC+9 固定）基準
- [ ] ハンコは自由選択モードでも、デイリーチャレンジモードでも押される（どのモードでも「その日に1回以上プレイした」ことが条件）

**優先度**: P0(必須)

**詳細仕様**: GDD §8「継続率設計」参照

#### FR-14: ゴースト生霊キャラクタ（第 3 の独自要素）

**ユーザーストーリー**:
セルフチャレンジャーとして、自己対戦の勝敗を抽象的な数字ではなく **「生霊の自分」との対話** として体験したい。過去の自分がキャラクタとして隣に立ち、声援や励ましで導いてくれることで、毎日のプレイが「ただのスコア記録」から「自分との物語」に変わる。

**コンセプト**:
ゴーストシステム（FR-02）のデータを、**視覚・ナラティブ層**として「ユーザ自身の生霊」キャラクタで表現する。競合脳トレアプリにゼロの独自要素。

- **機械的**: 直近 5 回プレイの統計（FR-02 既存、変更なし）
- **視覚的**: 半透明の白いかわいいゴーストキャラ（全画面共通再利用コンポーネント）
- **物語的**: "昨日の自分" の生霊が横に立ち、対話式に案内する

**指標 → ゴースト表現の対応** (GDD §5e / memory/project_ghost_character.md と同期):

| 指標 | ゴーストへの反映 | バージョン |
|---|---|---|
| 精度 0〜100%（FR-05） | 不透明度 (alpha = 0.25 + accuracy × 0.75)。精度 0% は希薄、100% で完全現出 | **v1.0 MVP** |
| セリフ | 吹き出しテキスト（画面文脈で更新） | **v1.0 MVP** |
| 脳年齢（FR-04） | 見た目年齢（体型・顔付き）。子/中/老 の 3 段階 | v1.1（要カスタムアセット） |
| ストリーク（FR-09） | オーラ・発光強度 | v1.1（要シェーダ） |
| ベスト更新 | 喜びモーション（ぴょんと跳ねる等） | v1.1（要 AnimationPlayer） |
| 表情バリエーション | idle / happy / tired / surprised / celebrating | v1.1（要ポーズ SVG × 5） |
| ゴースト対戦勝敗（FR-02） | セリフ + 表情変化（勝: 祝福、負: 励まし。赤色禁止ルールと整合） | セリフは v1.0、表情は v1.1 |

**受け入れ条件（v1.0 MVP）**:
- [ ] `scenes/ui/ghost_character.tscn` / `scripts/ui/ghost_character.gd` (class_name `GhostCharacter`) が再利用コンポーネントとして実装されている
- [ ] コンポーネントが **ホーム画面** でインスタンス化されている
- [ ] 精度を `set_accuracy(0.0〜1.0)` で渡すと不透明度に反映される（alpha = 0.25 + accuracy × 0.75）
- [ ] `set_dialogue(text)` でセリフが吹き出しに表示される
- [ ] `set_brain_age(int)` / `set_streak(int)` / `set_mood(string)` は API のみ予約（v1.0 では no-op 実装で OK）
- [ ] ダミーアセット `assets/characters/ghost_placeholder.svg` が存在し、カスタムアセット差し替えが可能な構造になっている
- [ ] セリフは **ユーザを「きみ」呼びで、やや幼めの親しみ口調**、ネガティブ表現・赤色使用禁止（GDD §6 / §5e セリフトーン規約と整合）
- [ ] 吹き出しは Theme variation `speech_bubble` を使用し、生 hex / 絶対配置 / add_theme_*_override を使わない（manifest.md §9 準拠。例外: `modulate.a` による不透明度制御は patterns.md §7 で正当化済み）

**受け入れ条件（v1.0 MVP の登場場面）**:
- [ ] ホーム画面: ログイン時の挨拶 + デイリーへの誘導セリフ
- [ ] オンボーディング画面 (FR-06): 初めての自己紹介セリフ（v1.0 実装範囲）
- [ ] 個別結果画面 (FR-08): 勝敗に応じたセリフ更新
- [ ] 総合結果画面 (FR-08): ベスト更新時の祝福セリフ
- [ ] ストリーク復帰演出 (FR-09): 2〜7 日ぶり再開時の特別セリフ

**スコープ外（v1.1 以降）**:
- カスタムアセット（5 ポーズ × 3 年齢層 = 15 枚）の発注と差し替え
- `set_brain_age` / `set_streak` / `set_mood` の本実装
- AnimationPlayer による喜びモーション
- ゲームプレイ中の小アバター化

**優先度**: P0(必須) ※ v1.0 MVP 範囲（API + ホーム登場 + セリフ更新）のみ

**詳細仕様**:
- GDD §5e「ゴースト生霊キャラクタ」
- `docs/functional-design.md` A-10「GhostCharacter コンポーネント」
- `docs/design/patterns.md` §5「ゴーストキャラクタ (生霊システム) の使い方」

| アプリ起動時間 | 3秒以内（Android）/ 5秒以内（Web版） | Galaxy A シリーズ（中位機）基準 |
| ホーム → ゲーム開始 | カウントダウン含め2秒以内 | |
| 各ミニゲームのフレームレート | 60fps 維持 | プレイ中のカクつきゼロ |
| 入力レイテンシ（反射タップゲーム） | 16ms 以内 | 反応時間計測の精度担保 |
| Web版の総アセットサイズ | 20MB 以下 | モバイル回線での初回ロード許容範囲 |

### ユーザビリティ

| 要件 | 基準 |
|---|---|
| 初回ユーザーが初起動から 30秒以内に 1種目目のゲームをプレイ開始できる |
| 2回目以降のユーザーが起動から 10秒以内にデイリーチャレンジを開始できる（スキップボタン経由） |
| 3種のデイリーチャレンジ完走までの所要時間が約2分（±30秒）に収まる |
| 全画面でタップ操作のみ。マルチタッチ・スワイプ・長押しを必須とする操作は存在しない |
| 数字表示のフォントサイズは**最低 20sp**、重要スコアは**24sp以上** |

### 信頼性

| 要件 | 基準 |
|---|---|
| データ損失ゼロ（アプリクラッシュ後も直前のプレイログが保持される） |
| 保存データが壊れても、起動ループに陥らず初期化して継続できる |
| クラッシュ率 < 1%（Android版、Google Play Console 基準） |
| ネットワーク切断中でもすべての機能が動作する（オフライン完全対応） |

### セキュリティ・プライバシー

| 要件 | 基準 |
|---|---|
| 個人情報を取得しない（ユーザー名・メールアドレス・位置情報 等） |
| プライバシーポリシーを ReigalLabs 名義で事前準備し、ストア掲載 |
| AdMob のデータ収集は Google の標準設定に従い、必要最小限に留める |
| Web版のシェアURLはスコアと日付のみで、個人特定情報を含まない |
| COPPA/GDPR 配慮: 13歳未満への広告配信を制限する（AdMob設定） |

### スケーラビリティ

| 要件 | 基準 |
|---|---|
| Web版は Cloudflare Pages の静的配信でスケールする（既存インフラ流用） |
| ローカル保存データは JSON 1ファイル < 100KB 想定（1年使用でも余裕） |
| データフォーマットはバージョン番号付きで、将来のマイグレーションに対応 |
| レーダーチャートの能力軸は**6つで固定**。将来ゲーム追加時も軸を増やさない |

### アクセシビリティ

| 要件 | 基準 | MVP 範囲 |
|---|---|---|
| **BGM・効果音の個別オンオフを設定画面で提供する** | 設定画面に2つのトグル（BGM / SE） | **MVP必須** |
| オーディオフォーカスを奪わない（Spotifyなどと共存可能） | `AudioStream.mix_target` を適切に設定 | **MVP必須** |
| 最低文字サイズ 14sp、重要数字 24sp 以上 | 全画面を対象 | **MVP必須** |
| 音量スライダー（BGM/SE 個別） | 設定画面に2つのスライダー | v1.4 |
| **色覚配慮モード**（色 + 形状の二重エンコード） | ストループの●▲■併記など | v1.4（MVP ではストループのみ簡易配慮を検討） |

### 法務・コンテンツ

| 要件 | 基準 |
|---|---|
| 脳年齢表示に「**エンターテインメント目的**」の注記を付ける。医学的効果・診断効果を謳わない |
| Google Play のコンテンツガイドラインに準拠（年齢区分、ターゲット年齢設定） |
| 特商法表記は ReigalLabs 名義で実施（既存サイトに掲載済み） |
| AdMob の広告ポリシー（不適切広告のフィルタリング）を設定 |

## スコープ外（明示的に含めない項目）

### MVP でやらないこと

- **サーバーサイド機能**: ランキング、リアルタイム対戦、クラウドセーブは MVP では実装しない
- **脳タイプ診断**（MBTIライク）: v1.2以降。命名・タイプ数・相性の設計が固まるまで保留
- **月次レポート**: v1.2
- **トレンドグラフ**: v1.2
- **プッシュ通知**: v1.3
- **iOS版**: v2.1 以降、収益次第
- **英語対応**: v2.0 以降
- **Web版広告**: AdSense 承認まで掲載しない
- **サブスクリプション課金**: 採用しない（競合の失敗要因）
- **知識問題・語彙問題**: 恒久的に採用しない（全ゲーム言語非依存）
- **マルチタッチ・スワイプ操作**: 恒久的に採用しない
- **ネガティブ色（赤）の使用**: 恒久的に採用しない（負け表示はグレー固定）
- **医学的効果の訴求**: 恒久的に採用しない（「エンターテインメント目的」を明示）
- **ユーザーアカウント登録**: 完全匿名で動作する
- **広告非表示以外の課金要素**: 追加ゲーム個別課金・ヒント課金なども採用しない

### 設計判断として確定していること

- **広告非表示課金は MVP に含める**（継続率の高いロイヤルユーザーを初日から取りこぼさない）
- **ゲーム間広告・プレイ中広告は絶対に実装しない**（競合の最大の失敗パターン）
- **ストリーク途切れペナルティは実装しない**（既存アプリの最大の不満）
- **能力軸は6つで固定**（ゲームが増えても軸は増やさない）
