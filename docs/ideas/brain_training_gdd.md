## 1. コンセプト

**「毎日2分、昨日の自分に挑め」**

ミニゲーム詰め合わせ型の脳トレアプリ。
1プレイ約2分で完結。「いつもの自分」をゴーストとして記録し、毎日の対戦で成長を実感する。さらに、そのゴーストを **ユーザ自身の生霊キャラクタ** として全画面に登場させ、精度 % に応じた現出度・対話式の案内で "鏡" のように寄り添う（§5e）。

## 2. ターゲットユーザー

### 年齢・性別ではなく「動機」で定義する

「20〜40代」は広すぎてUI/UXの判断基準にならない。
このアプリの独自要素（ゴースト対戦・ゴースト生霊キャラクタ・デイリーシード・シェアURL）から逆算して、
**「なぜこのアプリを開くか」の動機**で2つのペルソナを定義する。

### ペルソナの優先順位

| | ペルソナ1: セルフチャレンジャー | ペルソナ2: ライトコンペティター |
|---|---|---|
| 役割 | **DAUと収益の主軸** | **バイラル拡散の手段** |
| 設計の優先度 | 高（このユーザーが離脱したら収益が死ぬ） | 中（このユーザーが広めてくれないと成長しない） |
| 迷ったときの判断基準 | ペルソナ1を優先する | ペルソナ2のためにペルソナ1の体験を犠牲にしない |

### ペルソナ1: セルフチャレンジャー（自己改善型）

| 項目 | 内容 |
|------|------|
| 動機 | 自分の成長を数字で実感したい。昨日の自分より良くなりたい |
| 利用シーン | 通勤電車の中。毎朝のルーティンとして2分プレイ |
| 刺さる機能 | ゴースト対戦（「いつもの自分に勝った！」）、スコア前回比、ベスト更新 |
| 行動パターン | 毎日欠かさずデイリーをやる。ストリークを大事にする。シェアは頻繁にしない |
| 離脱リスク | スコアが停滞して成長実感がなくなったとき |
| 対策 | 難易度の動的調整、レーダーチャートの弱点導線で新しい挑戦を提示 |

**例**: 30代会社員。朝の電車で毎日やる。Wordleの代わりに。スコアが上がると嬉しいけど、Xにシェアするほどではない。ゴーストに負けた日は帰りの電車でもう1回やる。

### ペルソナ2: ライトコンペティター（社交型）

| 項目 | 内容 |
|------|------|
| 動機 | 友達やフォロワーとライトに競いたい。結果を見せたい |
| 利用シーン | 友達がシェアしたURLから流入。「勝てる？」に乗せられてプレイ |
| 刺さる機能 | デイリーシード共通化（同じ問題で比較）、シェアURL、OGPカード |
| 行動パターン | 毎日はやらない。友達がシェアしたときにだけやる。結果は必ずシェアする |
| 離脱リスク | 周りが飽きたら自分もやめる |
| 対策 | Web版の手軽さ（インストール不要）で参入障壁を下げる。シェア画像の質を上げる |

**例**: 25歳。Xのねこぽの投稿を見て「俺もやってみよ」。Web版でサクッとプレイ。結果をXに貼る。1週間後に忘れるが、また誰かのシェアで思い出す。

### ペルソナがUI/UXに与える影響

| UI/UX判断 | ペルソナ1（セルフチャレンジャー）の要求 | ペルソナ2（ライトコンペティター）の要求 | 設計方針 |
|-----------|--------------------------------------|---------------------------------------|---------|
| 結果画面の優先順位 | スコア前回比 → ゴースト勝敗 → 脳年齢 | スコアの絶対値 → シェアボタン | スコア前回比を最上部に。シェアボタンは目立つ位置に常時表示 |
| ゴースト表示 | 毎日見るので控えめでOK | 初回でインパクトが必要 | プログレスバーは小さく。勝敗結果は大きな演出 |
| シェア画像 | あまり使わない | 最重要。映えないとシェアしない | OGPカードのデザインに工数をかける |
| 初回体験 | 全6種やり切る傾向 | 1〜2種で離脱する傾向 | 途中離脱OK＋暫定脳年齢＋ロック表示で両方に対応済み |
| トーン | 「成長した」が嬉しい | 「勝った」が嬉しい | 「いつもの自分に勝利！」は両方に刺さる |
| 色使い | スコア上昇=ポジティブカラー（緑/青）で成長を実感 | 勝敗の色分け（勝ち=金/緑、負け=グレー）で結果が一目瞭然 | ポジティブ色を基調。負けてもネガティブ色（赤）は使わない |
| フォント | 数字の視認性最優先。スコアは大きく太く | シェア画像上での可読性 | スコア表示は24sp以上。ゲーム中の数字は20sp以上 |
| 情報密度 | 詳細データも見たい（レーダーチャート、ベスト記録一覧） | 結果はシンプルに。スコアとゴースト勝敗だけでいい | 結果画面は「サマリー＋スクロールで詳細」の2層構成 |

### 初動の獲得戦略

| チャネル | 対象ペルソナ | 施策 |
|---------|-----------|------|
| ねこぽのX投稿 | 両方 | デイリースコアのシェア投稿。フォロワーがURL経由でWeb版に流入 |
| Web版シェアURL | ペルソナ2 | 「勝てる？」でバイラル。インストール不要で参入障壁ゼロ |
| Google Play検索 | ペルソナ1 | ASO最適化。「脳トレ」「自分対戦」で検索ヒット |
| 口コミ | ペルソナ2→ペルソナ1 | ライトコンペティターが広め、セルフチャレンジャーが定着する |

### 言語・地域
- **言語**: 日本語のみ（v1.0）
- **地域**: 日本国内
- **将来**: v2.0で英語対応。ゲームが言語非依存なのでローカライズコストは低い

## 3. プラットフォーム戦略・技術スタック

### マルチプラットフォーム方針

Godot 4の単一コードベースから**Web版（HTML5）とAndroid版を同時にエクスポート**する。

```
Godot 4 プロジェクト（GDScript）
  ├── Web Export (HTML5) → brain.reigals.com
  │     ├── 広告: なし（AdSense未承認。当面デモ＆フィードバック用途）
  │     ├── 役割: 先行公開。テストプレイ＆フィードバック収集
  │     └── ホスト: Cloudflare Pages（既存インフラ流用）
  │
  └── Android Export (APK/AAB) → Google Play
        ├── 広告: AdMob（収益の本丸）
        ├── 役割: メイン配信。テスター募集 → 正式リリース
        └── 注意: テスター14日間の審査期間あり
```

### なぜ並行開発か

| 観点 | Web版 | Android版 |
|------|-------|----------|
| 公開速度 | 即公開可能 | テスター募集→14日審査→正式公開 |
| フィードバック | URL共有だけで遊んでもらえる | インストール必要 |
| 収益化 | 当面なし（AdSense未承認） | AdMobで即収益化 |
| ユーザー体験 | スマホブラウザで手軽 | ネイティブで快適 |
| X/SNS連携 | リンク1つで拡散可能 | ストアURL共有 |

→ **Web版で素早くフィードバックを集め、Android版テスター期間中に改善を回す**

### 技術スタック

| 項目 | 選定 | 備考 |
|------|------|------|
| エンジン | Godot 4（GDScript） | Web/Android両方にエクスポート可能 |
| Web版ホスト | Cloudflare Pages | brain.reigals.com（サブドメイン） |
| Web版広告 | なし（当面） | AdSense承認後に追加可能 |
| Android版配信 | Google Play（$25登録） | テスター14日間要注意 |
| Android版広告 | AdMob（godot-admob-plugin） | godot-sdk-integrations版 |
| アート | フリー素材 + Godot UIテーマ | アイコン等は最低限自作 |
| データ保存 | ローカル JSON | Web: localStorage / Android: user:// |
| 分析 | Firebase Analytics | v1.1以降でAndroid版に導入 |

### Web版の技術的注意点

- Godot 4のWeb Exportは SharedArrayBuffer が必要 → HTTPSヘッダーの COOP/COEP 設定
- Cloudflare Pagesの _headers ファイルで設定可能
- モバイルブラウザでのタッチ操作をテスト必須（viewport meta, touch-action CSS）
- 音声の自動再生制限 → ユーザーインタラクション後に AudioServer を初期化
- Web版ではAdMobは使えない（JavaScript SDKではなくネイティブプラグイン）

## 4. ミニゲーム設計（MVP: 6種）

### 設計原則（競合調査 + ペルソナから導出）

1. **全ゲーム言語非依存**: 四字熟語・語彙系は入れない（PEAKと毎日脳トレで「知識問題は不適切」と炎上済み）
2. **操作はタップのみ**: マルチタッチ・スワイプは使わない（PEAKで「操作が制御できない」と不満）
3. **パラメトリック生成**: 問題パターンを毎回変える（みんなの脳トレで「慣れると年齢下がるだけ」と指摘済み）
4. **各ゲーム1〜2日で実装可能なスコープ**: 初回フローの「直感的に理解しやすい順」に開発（ゴースト7番勝負→暗算→数字さがし→ストループ→順番記憶→神経衰弱）
5. **日付シードでパラメトリック生成**: デイリーチャレンジは全ユーザー共通問題（Wordle方式）
6. **最初の2種は「これだけでも楽しい」を成立させる**:
   - ペルソナ2（ライトコンペティター）は1〜2種で離脱する可能性が高い
   - 初回順序の最初の2種（ゴースト7番勝負・フラッシュ暗算）は、ルール説明なしでも遊べて、スコアの上下が直感的にわかり、1回で「もう1回やりたい」と思えること
   - この2種のクオリティがアプリ全体の第一印象を決める

### 各ゲーム詳細

#### 4-1. フラッシュ暗算（計算力）
- **ルール**: 画面に数字が次々と表示され、合計を回答
- **時間**: 30秒
- **パラメトリック要素**: 数字の桁数・表示速度・個数・演算子（＋のみ → ＋−混合）
- **パクリ元**: みんなの脳トレ「計算力」、毎日脳トレ「計算道場」
- **改善点**: テンキー入力UI（みんなの脳トレは選択式で簡単すぎるとの声あり）
- **Godot学習**: Label, Timer, 基本的なシーン遷移

#### 4-2. 順番記憶（短期記憶力）
- **ルール**: N個のパネルが順番に光り、同じ順番でタップ
- **時間**: パネル数に応じて可変（正解するたびにN+1）
- **パラメトリック要素**: パネル配置のランダム化、光るパターン毎回変化
- **パクリ元**: みんなの脳トレ「記憶力」、毎日脳トレ「順番記憶」
- **改善点**: カードの並びで誤差が出る問題（みんなの脳トレのレビュー指摘）をランダム配置で解決
- **Godot学習**: GridContainer, Tween, 入力処理

#### 4-3. 色文字テスト / ストループ（注意力・判断力）
- **ルール**: 「赤」と青色で書かれた文字 → 文字の「色」を答える
- **時間**: 30秒間に何問正解できるか
- **パラメトリック要素**: 色と文字の組み合わせをランダム生成、選択肢の配置もランダム
- **パクリ元**: みんなの脳トレ「判断力」
- **改善点**: 色覚配慮モード追加（みんなの脳トレで「色弱にはムリ」と指摘済み）→ 文字の下に形状アイコン（●▲■）を併記
- **Godot学習**: RichTextLabel, カラー操作, ボタン動的生成

#### 4-4. ゴースト7番勝負（反応速度）

- **ルール**: 予告→ターゲット移動→ゴーストラインに到達する瞬間にタップ。1 ゲーム 7 ラウンドの決闘制。中央 5 ラウンドの平均反応時間（ラインとタップの時刻差）でスコア算出
- **時間**: 約 30 秒（1 ラウンド 2〜3 秒 × 7 + 開始・終了演出）
- **パラメトリック要素**: ターゲット出現方向（左/右/上/下）、移動速度（遅/中/速/最速の 4 段階）、予告遅延（0.5〜1.5 秒ランダム）。デイリーシードで全員共通のパターンを生成
- **パクリ元**:
  - **反応時間計測の妥当性**: Human Benchmark（5 trials 平均が世界標準）、反射神経検定（一発勝負/ランダム/3 連続のモード制）
  - **予告可能性とリズム**: Piano Tiles 2（落下タップ、Reddot Design Award 受賞）
  - **ゴースト対戦との接続**: レースゲームのゴースト機能（本アプリの §5b 既存要素）
- **改善点**:
  - **ランダム位置タップの単調さを解消**: Piano Tiles 型の "予告可能性"（どこに来るかわかる、いつ来るかがカギ）を導入
  - **Human Benchmark の "ただ待つだけ" を解消**: 予告→移動の緊張感で 30 秒を演出で埋める
  - **みんなの脳トレ「反応力」の後出しじゃんけん不満を回避**: 純粋な反応速度計測に回帰
  - **脳トレ覚醒の "端タップでミス判定" レビュー不満を解消**: 判定領域を視覚より 10〜15% 広めに設定
  - **外れ値の影響を排除**: 7 発中、最速 1 発と最遅 1 発を除いた中央 5 発の平均で計測（フライング・瞬きの影響を除去）
- **独自要素**: 「いつもの自分」が決闘相手として登場。各ラウンドごとに勝敗が確定し、7 戦通算で「5 勝 2 敗」のように結果が出る。OGP 画像・X シェアとの相性が抜群
- **ゴースト生霊キャラクタとの接続** (§5e): 7 番勝負の間だけ、生霊は "対戦相手モード"（真剣な表情）になる。試合後は通常の "相棒モード"（励ます／讃える）に戻る。マスターとサーヴァントがリング上で戦い、試合後は握手する構造
- **Godot 学習**: Tween（ターゲット移動アニメーション）, Timer（予告遅延）, InputEventScreenTouch, カスタム判定ロジック

詳細設計は別紙 `docs/specs/ghost-7ban-shobu-spec.md` 参照。

#### 4-5. 神経衰弱ライト（記憶力・観察力）
- **ルール**: 4×4のカードを裏返してペアを探す
- **時間**: クリアまでのタップ数 × タイム で評価
- **パラメトリック要素**: カードの種類（数字・色・図形）と配置を毎回ランダム
- **パクリ元**: みんなの脳トレ「記憶力」（数字記憶揃え）
- **改善点**: みんなの脳トレは「神経衰弱みたいな問題は出てくるカードの並びですごく誤差が出る」→ 完全ランダム化で公平性担保
- **Godot学習**: TextureRect, アニメーション, 状態管理

#### 4-6. 数字さがし（注意力・観察力）
- **ルール**: 1〜25の数字をランダム配置から昇順にタップ
- **時間**: クリアタイムで評価
- **パラメトリック要素**: 数字の位置・フォントサイズ・色をランダム化
- **パクリ元**: みんなの脳トレ「観察力」（1〜25タップ）、脳トレ！数字さがし
- **改善点**: 数字さがしアプリのレビュー「広告が多く割込み集中力を妨げる」→ プレイ中広告なし
- **Godot学習**: カスタムUI配置, スコア計算

## 5. UXフロー

### 初回フロー

初めてアプリを開いた人向けの「脳力測定テスト」。チュートリアル兼初期データ収集兼脳年齢の初回表示を全部兼ねる。

**1種でも暫定脳年齢は出る。** ただし全6種やらないとゴースト対戦・レーダーチャート・正式脳年齢が解放されない。

```
  ↓                        ├── 暫定脳年齢 + 精度（17%: 1/6種）

  ↓                        ├── 🔒 能力レーダー   │ 精度100%で解放

  └── [ホームへ]
```

**精度の表示:**

精度は**パーセント表示**。ゲーム種数に依存しない設計。

```
精度 = プレイ済み種目数 / 全種目数 × 100%
```

| プレイ状況 | 精度表示 | 脳年齢の表記 | 解放状態 |
|-----------|---------|------------|---------|
| 1/6種 | 精度 17% | 約○○歳 | ゴースト🔒 レーダー🔒 |
| 3/6種 | 精度 50% | 約○○歳 | ゴースト🔒 レーダー🔒 |
| 5/6種 | 精度 83% | 約○○歳 | ゴースト🔒 レーダー🔒 |
| 6/6種 | 精度 100% | ○○歳（確定）| ゴースト🔓 レーダー🔓 |

v1.1でゲームが9種に増えても同じ式で動く。精度100%の到達条件は「その時点の全種目をプレイ済み」。
新ゲーム追加時は精度が自動的に下がり（6/9=67%）、新ゲームをプレイする動機になる。

**UI表示イメージ:**
```
脳年齢: 約32歳
測定精度: ████████░░░░ 67%（6/9種プレイ済み）
           新ゲーム「空間認知」をプレイすると精度UP！
```

**設計意図:**
1. **1種でも脳年齢が出る** — 即時フィードバックの原則。「結果が出ない」は離脱の原因
2. **精度のパーセント表示** — ツァイガルニク効果（未完了が気になる心理）で全6種への動機
3. **ゴースト対戦をロック表示** — 最大のフックが「まだ使えない」のは強い動機になる
4. **途中離脱OK** — 未プレイ種目はホームの「全ゲーム一覧」からいつでもプレイ可能
5. **レーダーチャートは6種完了の目玉として温存** — 3種で出すと「もう満足」で残り3種をやらないリスク

**初回のゲーム順序（直感的に理解しやすい順）:**
1. ゴースト7番勝負 ← 「予告が来たらタップ」説明不要レベル（反射速度）
2. フラッシュ暗算 ← 数字を足すだけ
3. 数字さがし ← 1から順番に押すだけ
4. ストループ ← ここからルール説明が重要
5. 順番記憶 ← パネルの順番を覚える
6. 神経衰弱 ← 最も操作が複雑

## 5b. ゴースト対戦システム

**既存の脳トレアプリにゼロの独自要素。** レースゲームのゴースト機能を脳トレに転用する。

### コンセプト

「昨日の自分」ではなく「いつもの自分」と対戦する。

- 比較対象: **直近5回のプレイ平均**
- 表示名: 「いつもの自分」（「平均」より物語性がある）
- ベスト記録は別枠で常時表示

### なぜ「直近5回平均」か

| 比較対象 | メリット | デメリット | 採用 |
|---------|---------|-----------|------|
| 昨日の自分 | 毎日ストーリーがある | 昨日が異常値だと楽勝 or 絶望 | ❌ |
| 過去ベスト | 目標が明確 | 毎日負け続けてモチベ死 | ❌ |
| 直近5回平均 | 勝率が約50%に自然収束。フロー状態 | 「平均」だと物語が弱い | ✅ |

→ 「直近5回平均」を採用し、表示名を「いつもの自分」にすることで物語性を補う

### ゲームタイプ別のゴースト表示

| ゲームタイプ | プレイ中の表示 | 結果画面の表示 |
|------------|--------------|-------------|
| **タイム系**（暗算・ストループ） | 画面下部にプログレスバー2本（自分 vs いつもの自分） | 「いつもの自分に勝利！ +2問差」 |
| **決闘系**（ゴースト7番勝負） | 各ラウンドごとに勝敗判定を即時表示。通算スコアを「👤 3勝 👻 1勝」形式で画面上部に表示 | 「ゴースト7番勝負 5勝2敗！」 |
| **クリア系**（順番記憶・神経衰弱・数字さがし） | ゴースト非表示（操作の邪魔になるため） | 「いつもの自分: 42秒 → 今日: 38秒 🎉勝利！」 |

### タイム系ゲームのゴーストUI

```
┌─────────────────────────────────┐
│  フラッシュ暗算      残り 18秒   │
│                                 │
│         「 23 + 47 = ? 」        │
│                                 │
│          [  70  ]               │
│                                 │
├─────────────────────────────────┤
│  👤 今日:       ████████░░ 8問  │
│  👻 いつもの自分: ██████░░░░ 6問 │
│  ─────────────────────────      │
│  ⭐ ベスト: 14問（4/3）          │
└─────────────────────────────────┘
```

- バーは控えめなサイズ（ゲーム画面を圧迫しない）
- チラ見で「勝ってる/負けてる」がわかる程度
- ゴーストの進捗は保存済みデータから再生（リアルタイムシミュレーション不要）

### 実装

```python

play_log = {
  "game": "flash_calc",
  "date": "2026-04-08",

    {"time_ms": 2300, "correct": true},

    {"time_ms": 6800, "correct": false},
```

## 5c. デイリーチャレンジ共通化

**全ユーザーが同じ問題を解く。Wordle方式。**

### なぜ共通化するか

Wordleがバズった最大の理由は「全員が同じ問題を解いているから結果を比較できる」こと。
脳トレでこれをやってるアプリは調査範囲で**ゼロ**。

### 実装: 日付シードによるパラメトリック生成

```gdscript
# 日付からシード値を生成
func get_daily_seed() -> int:
    var date = Time.get_date_dict_from_system()
    return date.year * 10000 + date.month * 100 + date.day

# ゲームの問題生成にシードを使用
func generate_daily_challenge():
    var rng = RandomNumberGenerator.new()
    rng.seed = get_daily_seed()

    # これで全ユーザーが同じ問題を解く
    var numbers = []
    for i in range(10):
        numbers.append(rng.randi_range(1, 99))
    return numbers
```

- 実装コスト: **極めて低い**（シード値を固定するだけ）
- ゲーム選択もシードで決定（毎日6種から3種をランダム選出→全員同じ3種）
- 「今日のチャレンジ」として表示。自由選択モードとは別枠

### 共通化のメリット

1. **スコア比較が公平** — 同じ問題だから「俺の方が上」が成立する
2. **Web版URLシェアとの相性抜群** — 「今日のチャレンジやってみて→URL」
3. **X投稿のネタになる** — 「今日のデイリー3,230pts。勝てる？」
4. **ゴースト対戦と併用可能** — 「いつもの自分」と「友達のスコア」の2軸で比較

## 5e. ゴースト生霊キャラクタ

**第 3 の独自要素。** §5b のゴースト対戦（データ層）に対して、**視覚・ナラティブ層**を担う。ゴースト対戦で扱う「直近 5 回平均 = いつもの自分」の統計データを、**ユーザ自身の生霊キャラクタ** として全画面に登場させ、精度・脳年齢・ストリークの状態を "鏡" として見せる。

### コンセプト: ゴーストは "あなた" である

既存の脳トレアプリに "キャラクタ対話式 UX" を持つものはある（Duolingo の owl 等）。しかし **そのキャラクタがユーザ本人** というパターンは調査範囲でゼロ。ブレインゴースト では "昨日の自分に挑め" というキャッチコピーを文字通り可視化する:

- **機械的**: 直近 5 回プレイの統計（§5b 既存定義、変更なし）
- **視覚的**: 半透明の白いかわいいゴーストキャラ（全画面共通）
- **物語的**: "昨日の自分" の生霊があなたの隣にいて、一緒に走ってくれる **相棒兼鏡**

### なぜ "相棒キャラ" ではなく "ユーザの生霊" か

| フレーミング | メリット | デメリット | 採用 |
|---|---|---|---|
| 別キャラの相棒 (Duolingo owl 型) | 親しみやすい | 「なぜ脳トレアプリに？」の説明負債 | ❌ |
| ユーザ本人の生霊 | GDD §5b と完全整合。"鏡を見る" 体験 | キャラデザインの自由度が低い | ✅ |

特に重要な効果: **「過去の自分に負けた = 過去の自分が励ましてくれる」**。データ上は自己対戦の敗北イベントでも、UI 上は「他者からの慰め」として受け取れる。セルフケアの仕組みとして強い。

### ユーザ指標 → ゴースト表現の対応

| 指標 | ゴースト表現 | バージョン |
|---|---|---|
| **精度 0〜100%** (§5 / PRD FR-05) | **不透明度**（alpha = 0.25 + accuracy × 0.75）。精度 0% はほぼ透明、精度 100% でくっきり現出。§5 の精度システムを視覚化 | **v1.0 MVP** |
| **セリフ** | 吹き出しテキスト（画面文脈ごとに更新） | **v1.0 MVP** |
| **脳年齢** (PRD FR-04) | 見た目年齢（体型・髪・顔付き）。子 / 中 / 老 の 3 段階アセット | v1.1（アセット発注後） |
| **ストリーク** (FR-09) | オーラ・発光強度（シェーダ） | v1.1 |
| **ベスト更新** | 喜びモーション（ぴょんと跳ねる等） | v1.1（AnimationPlayer） |
| **表情バリエーション** | idle / happy / tired / surprised / celebrating の 5 ポーズ | v1.1 |

## 6. スコアリングシステム

MVPの評価システムは**スコア＋脳年齢＋ゴースト勝敗＋レーダーチャート**のシンプル構成。
脳タイプ診断はMVPには含めず、v1.2以降で面白い設計が固まったら再検討する。

### 各ミニゲームのスコア算出

| ゲーム | スコア要素 | 計算式イメージ |
|--------|----------|-------------|
| フラッシュ暗算 | 正答数 × 速度ボーナス | 正答1問=100点 + 残り秒数×10 |
| 順番記憶 | 到達パネル数 | N段クリア = N×150点 |
| ストループ | 正答数 / 30秒 | 正答1問=100点 − 誤答1回=50点 |
| ゴースト7番勝負 | 中央5発の平均反応時間 + 勝敗ボーナス | (1000 / 平均ms) × 300 + ゴースト勝利数 × 50 |
| 神経衰弱 | タップ効率 × タイム | (ペア数 / 総タップ数) × 1000 + 時間ボーナス |
| 数字さがし | クリアタイム | max(0, 3000 − クリア秒数×100) |

### 結果画面の設計（ペルソナ別2層構成）

結果画面は**「サマリー（ファーストビュー）」＋「スクロールで詳細」**の2層構成にする。
ペルソナ2（ライトコンペティター）はサマリーだけ見てシェアして離脱する。
ペルソナ1（セルフチャレンジャー）はスクロールして詳細を確認する。

```
┌──────────────────────────────────┐
│  📊 今日の結果                    │  ── ファーストビュー ──
│                                  │  ペルソナ2はここだけ見る
│  合計: 3,230 pts  ↑ +285        │  ← スコアと前回比が最上部
│  👻 いつもの自分に 2勝1敗！      │  ← ゴースト勝敗（勝ち=緑、負け=グレー）
│  脳年齢: 31歳（-3歳！）         │
│                                  │
│  [シェア]                        │  ← シェアボタンはスクロール前に配置
│                                  │
│  ──── スクロール ────            │  ── 詳細エリア ──
│                                  │  ペルソナ1はここまで見る
│  フラッシュ暗算  1,280 ↑+180    │
│  ゴースト7番勝負 900 ★BEST     │
│  ストループ     1,050 ↓-30      │
│                                  │
│  ┌─ 能力レーダーチャート ──┐     │
│  │      計算力               │     │
│  │   判断力   記憶力         │     │
│  │   観察力   注意力         │     │
│  │      反射速度             │     │
│  └──────────────────────┘     │
│  記憶力が弱点です → [鍛える]     │
│                                  │
│  [詳細分析(広告)]  [ホームに戻る] │
└──────────────────────────────────┘
```

**設計意図:**
- ファーストビューに「合計スコア＋ゴースト勝敗＋脳年齢＋シェアボタン」を収める
- ペルソナ2は3秒で結果を把握→シェア→離脱。この導線を妨げない
- ペルソナ1はスクロールして個別スコア・レーダーチャート・弱点導線を確認
- 負けても赤色は使わない。勝ち=緑/金、負け=グレー（ペルソナ1のモチベーションを守る）

### レーダーチャートの継続導線

レーダーチャートが「見て終わり」にならないよう、弱い能力から対応ゲームに直行できる導線を入れる。

| 弱い能力 | 誘導先ゲーム | 表示例 |
|---------|------------|--------|
| 計算力 | フラッシュ暗算 | 「計算力が弱点です → [鍛える]」 |
| 記憶力 | 順番記憶 | 「記憶力を鍛えよう → [鍛える]」 |
| 注意力 | ストループ | 「注意力が伸びしろ → [鍛える]」 |
| 反射速度 | ゴースト7番勝負 | 「反射速度を鍛えよう → [鍛える]」 |
| 観察力 | 数字さがし | 「観察力にチャレンジ → [鍛える]」 |
| 判断力 | 神経衰弱 | 「判断力を強化 → [鍛える]」 |

- デイリーチャレンジ（ランダム3種）とは別枠で、任意の追加プレイとして機能する
- 弱点補強で得たスコアも通常通り記録される
- 「弱点がない」（全能力が均等に高い）場合は表示しない

### 脳年齢のチューニング方針

脳年齢は合計スコアを「歳」に翻訳した表示値。

- 初回プレイは「実年齢 -3〜5歳」に出る調整（やや甘め）
- 最低でも「実年齢 +10歳」を超えないキャップ
- スコアが上がれば脳年齢も若返る

### トレンドグラフ（v1.2）
- 過去30日分の**スコア推移**グラフ（日々の成長実感）
- ゴースト戦績推移（勝率の変化）
- パクリ元: PEAKのパフォーマンスグラフ

### MVP後の拡張候補（v1.2以降）
- 脳タイプ診断（MBTIライクな分類。命名・タイプ数・相性の設計が固まったら）
- 月次レポート
- 全ユーザー中の偏差値/ランク表示

## 7. マネタイズ設計（競合の失敗から学ぶ）

### プラットフォーム別方針

| | Web版（brain.reigals.com） | Android版（Google Play） |
|---|---|---|
| 広告 | なし（当面） | AdMob（バナー/インタースティシャル/リワード） |
| 課金 | なし | 広告非表示 買い切り ¥300〜500（MVP） |
| 収益期待 | ゼロ（フィードバック＆デモ用途） | メイン収益源 |
| AdSense承認後 | バナー広告追加を検討 | — |

### 競合の広告問題まとめ

| アプリ | 問題 | 結果 |
|--------|------|------|
| 毎日脳トレ | 1ゲームごとに広告、時間制限中に強制広告 | 不満率42%（レビュー分析） |
| PEAK | 1プレイごとに広告2つ、サブスク月額600円 | 不満率75%（レビュー分析） |
| 数字さがし | 広告が割り込んで集中力妨害 | 低評価の直接原因 |

### 本アプリの広告設計

| 広告タイプ | タイミング | 頻度 | 根拠 |
|-----------|----------|------|------|
| バナー広告 | ホーム画面下部のみ | 常時 | ゲーム画面では非表示 |
| インタースティシャル | 全トレーニング完了後（結果→ホーム遷移時） | 3回に1回 | ゲーム間に挟まない |
| リワード広告 | 「詳細分析を見る」「もう1回チャレンジ」 | ユーザー任意 | 価値提供型 |

### 鉄則（競合の失敗を繰り返さない）
1. **ゲームプレイ中は絶対に広告を表示しない**
2. **ゲーム間に広告を挟まない**（総合テストの途中に広告 = 最悪のUX）
3. **サブスクリプションにしない**（PEAKの不満率75%の主因）
4. **広告非表示の買い切りオプションをMVPから用意**（¥300〜500）
   - 毎日脳トレで「有料でもいいので広告をなくしてほしい」の声が複数あるのに対応していない
   - 競合が放置している不満 = 最もロイヤルなユーザーを取りこぼしている
   - 課金ユーザーは継続率が最も高い層。MVP段階から受け皿を用意する
5. **スキップ不可の動画広告を使わない**
6. **広告表示中にフリーズする実装はテストで排除**

### ペルソナ別のマネタイズ特性

| | ペルソナ1: セルフチャレンジャー | ペルソナ2: ライトコンペティター |
|---|---|---|
| 利用頻度 | 毎日 | 週1〜2回（友達のシェア経由） |
| 広告接触 | 多い（毎日見る）→ 広告疲れリスク | 少ない → 広告は気にならない |
| 買い切り課金率 | **高い**（毎日使うから広告が邪魔） | 低い（たまにしか使わない） |
| リワード広告視聴 | 高い（詳細分析を見たい） | 低い（サマリーで満足） |
| 設計方針 | 広告非表示課金の主要ターゲット。課金誘導はホーム画面のさりげないバナーで | リワード広告は控えめに。シェア→流入の導線を邪魔しない |

### ペルソナ別の離脱パターンと対策

| | ペルソナ1: セルフチャレンジャー | ペルソナ2: ライトコンペティター |
|---|---|---|
| **主な離脱タイミング** | スコアが停滞して成長実感がなくなったとき（2〜3週間目） | 周りが飽きてシェアが減ったとき（1〜2週間目） |

| **対策3** | ゴーストの「直近5回平均」が自動調整されるので、停滞期でも「いつもの自分」との勝敗が接戦になる | Web版の手軽さ。インストール済みでなくてもURL1つで即プレイ |

## 10b. ミニゲーム追加時の成長戦略

ミニゲームは今後増える前提で設計する。v1.1で+3種（→計9種）、以降も追加可能。
追加時に壊れない設計ルールをここで定める。

### 影響範囲と対応ルール

| 要素 | MVP（6種） | v1.1（9種） | 対応ルール |
|------|----------|-----------|----------|
| **精度** | 6/6=100% | 6/9=67%に低下 | パーセント表示なので自動対応。新ゲームをプレイする動機になる |
| **脳年齢** | 6種の平均から算出 | 9種の平均から算出 | プレイ済み種目のみで平均する。未プレイ種目は算出対象外 |
| **デイリーチャレンジ** | 6種から3種選出 | 9種から3種選出 | シード方式なので自動対応。新ゲームもローテーションに入る |
| **ゴースト** | 全6種にデータ蓄積 | 新3種はデータなし | 新ゲームは初回「ゴーストなし」。2回目以降からゴースト対戦開始 |
| **レーダーチャート** | 6角形（6能力） | 6角形のまま | **能力軸は6つで固定。ゲームが増えても軸は増やさない** |
| **初回フロー** | 全6種で精度100% | 全9種で精度100% | 初回は最初の6種のみ実施。残り3種はホームから任意プレイ |
| **シェアURL** | 3種のスコア | 3種のスコア | デイリーは常に3種。ゲーム数に依存しない |

### レーダーチャートの能力軸は6で固定する理由

ゲームが増えるたびにレーダーチャートの軸が増えると、過去データとの比較ができなくなる。
能力軸は以下の6つで固定し、新ゲームは既存の能力軸にマッピングする。

| 能力軸 | MVP | v1.1追加分 |
|--------|-----|-----------|
| 計算力 | フラッシュ暗算 | — |
| 記憶力 | 順番記憶 | 瞬間記憶 |
| 注意力 | ストループ | — |
| 反射速度 | ゴースト7番勝負 | — |
| 観察力 | 数字さがし | — |
| 判断力 | 神経衰弱 | 推理、空間認知 |

→ 同じ能力軸に複数ゲームがある場合、その能力のスコアは平均値で算出。
→ ゲームが増えるほど各能力のスコアが安定する（サンプル数が増える）。

### 新ゲーム追加時のユーザー体験

```
v1.1アップデート後、ユーザーがアプリを開く
  ↓
ホーム画面に通知バッジ: 「新しいゲームが3種追加されました！」
  ↓
全ゲーム一覧に新ゲームが [NEW] タグ付きで表示
  ↓
脳年齢の精度が 100% → 67% に低下
  ├── 「測定精度が下がりました。新ゲームをプレイして精度を回復しよう」
  └── 精度100%への再到達が新ゲームプレイの動機になる
  ↓
新ゲームを全種プレイ → 精度100%に復帰 🎉
```

この設計なら、ゲーム追加のたびに「精度を回復する」という自然なリプレイ動機が生まれる。
精度低下は「ペナルティ」ではなく「新しいチャレンジ」としてポジティブに見せる。

## 11. アプリ名・ストア訴求

### 命名方針

既存アプリと検索で並んだとき「これは違う」と一目でわかる名前にする。
ゴースト対戦がこのアプリ最大の独自要素なので、名前に反映する。

| 候補 | ストア掲載名（サブタイトル含む） | 狙い |
|------|-------------------------------|------|
| **脳トレバトル** | 脳トレバトル - 昨日の自分に勝て | ゴースト対戦が一目でわかる。「バトル」で他アプリと差別化 |
| **脳トレゴースト** | 脳トレゴースト - 毎日2分の自分対戦 | ゴースト直球。ゲーマー層に刺さる |
| **ブレインダッシュ** | ブレインダッシュ - 脳トレ×自分対戦 | スピード感。カタカナで若年層向き |
| **脳トレ vs 自分** | 脳トレ vs 自分 - 2分で脳年齢測定 | 「vs」で対戦感。ASO的に「脳トレ」が頭にある |

※ 最終決定は開発終盤。Web版先行公開時のフィードバックで反応を見る

### ストア説明文（ペルソナ別訴求）

Google Playの検索結果で見える1行目に差別化を入れる。
**ペルソナ1（自己改善）とペルソナ2（社交）の両方に刺さる1行を作る。**

```
❌ 6種のミニゲームで脳年齢を測定！毎日トレーニングしよう
   → 既存アプリと同じ。埋もれる

✅ 「いつもの自分」と毎日対戦。友達と同じ問題で脳トレ対決。
   → 前半: ペルソナ1に刺さる（ゴースト対戦）
   → 後半: ペルソナ2に刺さる（デイリーシード共通化）
```

### ストア説明文の詳細（展開後に見える部分）

```
■ 自分との対戦
毎日のプレイ結果を「いつもの自分」として記録。
今日の自分は昨日の自分に勝てるか？

■ 友達と同じ問題で対決
デイリーチャレンジは全員共通。
URLを送るだけで友達も同じ問題に挑戦できます。

■ たった2分で完結
デイリーチャレンジは3種×30秒。通勤中にサクッと。
全6種やっても約5分。

■ 広告が邪魔しない
ゲーム中は広告ゼロ。プレイに集中できます。
```
