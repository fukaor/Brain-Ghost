## 1. 概要

### 1-1. コンセプト

**「記憶の精度を、タップの無駄なさで証明する神経衰弱ライト」**

GDD §4-5 の基本設計を深掘りし、**タップ効率（ペア数×2 ÷ 総タップ数）× クリアタイム**の複合スコアで、既存の神経衰弱ゲームの「正解するのが当たり前で差がつかない」「時間だけの勝負になる」問題を構造的に解決する。

### 1-1b. ゲーム名と命名体系

GDD の命名体系（色文字ストループ spec §1-1b 参照）に準拠:
- 本ゲームは**クリア系**（プレイ中ゴースト非表示、結果画面で比較）
- 日本語名体系を採用: **「神経衰弱ライト」**
- 「ライト」= 4×4（8 ペア）の軽量版。グリッド拡張はティア進行で段階解放

### 1-2. 核のメカニクス

```
[カード記憶]  →  [1枚目タップ]  →  [2枚目タップ]  →  [ペア判定]  →  [繰り返し]
  短期記憶        選択             照合              即時          全ペア揃えるまで
```

1. 4×4 グリッド（8 ペア）のカードが裏向きで配置される
2. 2 枚のカードを順番にタップして表にする
3. 同じ絵柄ならペア成立（表のまま固定）、違えば裏に戻る
4. 全ペアを揃えるまでのタップ数とクリアタイムで評価

### 1-3. 差別化ポイント（競合類型との比較）

| 類型 | 代表例 | 問題点 | 本作の改善 |
|---|---|---|---|
| A. 対戦 AI 型 | nullhouse「脳トレ！神経衰弱！」 | AI 対戦は楽しいが脳トレの計測に不向き（AI の強さで結果が変わる） | **ゴースト対戦**で「過去の自分」と比較。公平な自己計測 |
| B. 時間のみ評価 | みんなの脳トレ「記憶力」 | 速度だけの勝負。雑にタップしても速ければ勝ち | **タップ効率**を重視。無駄タップが多いとスコアが下がる |
| C. カード配置固定 | みんなの脳トレ「記憶力」 | 「カードの並びですごく誤差が出る」（レビュー指摘） | **完全ランダム配置 + デイリーシード**で公平性担保 |
| D. 飽きやすい | 大半の神経衰弱アプリ | 同じ 4×4 を何度もやると飽きる | **ティア段階制**（グリッド拡張・シャッフル・二属性カード）で長期目標 |
| E. カード種が単一 | 多くの神経衰弱アプリ | パターン暗記で慣れる | **図形・色・数字をティアごとに切替**。認知チャネルを変える |
| F. 広告挿入 | 多くの無料神経衰弱アプリ | ゲーム間に広告、集中力途切れ | GDD §7 広告設計に準拠。プレイ中広告ゼロ |

### 1-4. 「ライト」の意味と時間原則

「ライト」は**プレイ時間の軽さ**を示す:

| | 神経衰弱ライト（本作） | 一般的な神経衰弱ゲーム |
|---|---|---|
| グリッド（MVP） | 4×4（8 ペア）| 6×6（18 ペア）以上 |
| プレイ時間 | 30〜60 秒 | 3〜10 分 |
| 設計思想 | 脳トレの 1 種目として短時間枠に収める | 神経衰弱をメインコンテンツとして遊ばせる |

**時間原則**: GDD §4 の「1ゲーム30秒」は基本単位だが、神経衰弱はクリアまでの所要時間が個人差が大きい。そのため**制限時間 60 秒を全ティア共通の上限**とする。ティアが上がるとグリッドが大きくなるが、制限時間は 60 秒のまま。これにより:
- デイリーチャレンジ「3種 × 約30〜60秒 = 約2〜3分」の想定が維持される
- 「60 秒でどこまでクリアできるか」が上位ティアのチャレンジになる

## 2. ゲームルール

### 2-1. 全体の流れ

```
┌─ クリアまでの流れ ─────────────────┐
│ 1. グリッド（ティアで決定）        │
│ 2. 1 枚目タップ → 表になる       │
│ 3. 2 枚目タップ → 表になる       │
│ 4. ペア判定                       │
│    ├ 一致 → 2枚とも表のまま固定  │
│    └ 不一致 → 0.5秒後に裏に戻る  │
│ 5. 全ペア揃う or 制限時間到達まで │
└───────────────────────────────────┘
  ↓
結果表示（スコア・前回比・ゴースト勝敗）
```

### 2-2. カードの内容（言語非依存）

GDD §4 設計原則 1「全ゲーム言語非依存」に完全準拠。カード表面は**図形・色・数字**のみ。

| ティア | カード内容 | ペア判定基準 | 認知チャネル |
|---|---|---|---|
| T1 | 単色の図形（赤い●、青い■ 等） | 同じ図形＋同じ色 | 視覚パターン認識 |
| T2 | 数字（1〜8） | 同じ数字 | 数字認識 |
| T3 | 二属性（赤い 3、青い 5 等） | 同じ数字＋同じ色 | 複合属性記憶 |
| T4 | 単色図形（10 種） | 同じ図形＋同じ色 | 拡張グリッドでの視覚記憶 |
| T5 | 二属性（12 種） | 同じ数字＋同じ色 | 拡張グリッド＋複合属性 |
| T6 | 単色図形（8 種）+ シャッフル | 同じ図形＋同じ色 | 位置記憶の無効化 |

**T1 の図形パレット**（8 ペア = 8 種類の図形）:

| # | 図形 | 色 | 視覚的特徴 |
|---|---|---|---|
| 1 | ● 円 | 赤 `#E53935` | 丸くて暖色 |
| 2 | ■ 正方形 | 青 `#1E88E5` | 角ばって寒色 |
| 3 | ▲ 三角形 | 緑 `#43A047` | 尖って中間色 |
| 4 | ◆ 菱形 | 黄 `#FDD835` | 回転した四角で明るい |
| 5 | ★ 星 | オレンジ `#FF6B35` | 複雑で暖色 |
| 6 | ⬡ 六角形 | 紫 `#7B1FA2` | 多角形で寒色 |
| 7 | ♥ ハート | ピンク `#EC407A` | 曲線で暖色 |
| 8 | ⬟ 五角形 | シアン `#00BCD4` | 多角形で寒色 |

**色覚配慮**: 図形の形状が全て異なるため、色だけに頼らずに区別可能。GDD §9 準拠。

### 2-3. 制限時間

**全ティア共通の制限時間上限: 60 秒**

| ティア | グリッド | ペア数 | 制限時間 | 設計意図 |
|---|---|---|---|---|
| T1 | 4×4 | 8 | 60 秒 | 初心者でもクリア可能 |
| T2 | 4×4 | 8 | 45 秒 | 時間プレッシャー追加 |
| T3 | 4×4 | 8 | 45 秒 | 二属性で記憶負荷 UP |
| T4 | 4×5 | 10 | 60 秒 | グリッド拡張（60 秒キャップ） |
| T5 | 4×6 | 12 | 60 秒 | さらに拡張（60 秒キャップ） |
| T6 | 4×4 + シャッフル | 8 | 60 秒 | 位置入替で記憶無効化 |

**v1.0 → v1.1 変更点**: T5 を旧 5×6（15 ペア / 90 秒）から **4×6（12 ペア / 60 秒）** に変更。理由:
- GDD §4 の「1ゲーム30秒」原則との乖離を最小化（60 秒は 2 倍だが、3 倍の 90 秒は許容範囲外）
- デイリーチャレンジ全体の所要時間を「約2〜3分」に収める
- 4×6 なら横幅が 4 列のまま維持され、画面制約問題（M2）も解消

**タイムアウト**: 制限時間内にクリアできなかった場合、その時点の成績（揃えたペア数・タップ数・経過時間）でスコアを算出。ゲームオーバーではなく「ここまでの結果」として表示。

### 2-4. カード裏面のデザイン

- ダークテーマに合わせた **濃い藍色の裏面** に薄いゴースト紋様
- 全カード同一デザイン（カード裏面で区別できてはいけない）
- タップ可能状態: カード周囲に微かなシアンの縁取り
- ペア成立済み: 表面のまま、彩度をやや落としてグレーアウト

### 2-5. タップ状態遷移と例外処理

カードには 3 つの排他的状態がある:

```
[face_down]  →  [face_up]  →  [matched]
   裏向き         表向き中        ペア成立済み
```

| 状態 | `is_face_up` | `is_matched` | タップ可能 |
|---|---|---|---|
| **face_down（裏向き）** | false | false | ✅ |
| **face_up（表向き中 = 1枚目として選択済み）** | true | false | ❌ 無視 |
| **matched（ペア成立済み）** | true | true | ❌ 無視 |

**例外処理**:

| ケース | 挙動 | 根拠 |
|---|---|---|
| 1枚目として表にしたカードを再タップ | 無視（何も起きない） | 誤タップ防止。タップカウントに加算しない |
| ペア成立済みカードをタップ | 無視 | 成立済みカードはゲーム的に「存在しない」扱い |
| ペア判定中（`is_processing = true`）にタップ | 無視 | 不一致時の 0.5 秒表示中にタップすると状態が壊れるため |
| 制限時間ちょうどにタップ | タップを有効とし、そのペア判定まで処理してから終了 | 最後の 1 タップで逆転クリアの可能性を残す |

### 3-2. ペア判定の演出

```
一致時（0.3 秒）:
  ✓ 2枚のカードが緑にフラッシュ → 彩度ダウンして固定

不一致時（0.5 秒）:
  × 2枚のカードがグレーにフラッシュ → 裏に戻る
  ※ 赤フラッシュは使わない（GDD §6 赤禁止ルール）
```

不一致時の裏返し待機時間 **0.5 秒** は重要。短すぎると 2 枚目を記憶する時間がない。長すぎるとテンポが悪い。競合調査で 0.3〜1.0 秒の範囲を確認し、0.5 秒を採用。

## 4. ティア段階制

GDD §5b の「ティア選択 + 段階的解放」原則に準拠。

### 4-1. ティア体系

| ティア | グリッド | ペア数 | カード内容 | 特殊ルール | 制限時間 | 難度倍率 | 行数 |
|---|---|---|---|---|---|---|---|
| **T1** | 4×4 | 8 | 単色図形 | なし | 60 秒 | ×1.0 | 4 |
| **T2** | 4×4 | 8 | 数字（1〜8） | なし | 45 秒 | ×1.2 | 4 |
| **T3** | 4×4 | 8 | 二属性（色+数字） | なし | 45 秒 | ×1.5 | 4 |
| **T4** | 4×5 | 10 | 単色図形（10 種） | なし | 60 秒 | ×1.8 | 5 |
| **T5** | 4×6 | 12 | 二属性（12 種） | なし | 60 秒 | ×2.2 | 6 |
| **T6** | 4×4 + シャッフル | 8 | 単色図形 | **シャッフル** | 60 秒 | ×2.8 | 4 |

**設計原則: 列数 4 固定、行数で拡張、制限時間 60 秒キャップ**

### 4-2. シャッフルルール（T6）

nullhouse「脳トレ！神経衰弱！」の「シャッフル衰弱」から着想:

```
ペアを 1 つ揃えるたびに、残りの裏向きカードの位置がランダムに入れ替わる
```

- 表面固定済み（ペア成立済み）のカードは移動しない
- シャッフルアニメーション: 0.3 秒（カードがスライドして新しい位置に移動）
- 「さっきあそこにあった」の記憶が無効化される → 短期記憶の再構築を強制

### 4-3. 解放条件

```
解放条件: 現在ティアで直近 5 回中 3 回、クリア + タップ効率 70% 以上を達成
```

**条件の明確化**:
- **クリア必須**: タイムアウト（未クリア）はどれだけ効率が高くても解放条件を満たさない
- **タップ効率 70%**: `(ペア成立数 × 2) / 総タップ数 × 100%`
- 例: 8 ペア全クリア、22 タップ → 16/22 = 72.7% → 条件達成
- 例: 6/8 ペア（タイムアウト）、効率 90% → クリアしていないため条件不達成

T1 は初回から解放。各ティア独立のゴーストデータを保持。解放は再ロックしない。

## 5. スコア算出

### 5-1. スコア計算式

```gdscript
func calculate_memory_score(pairs: int, total_taps: int,
    clear_time_sec: float, time_limit_sec: float,
    tier_multiplier: float) -> int:

    # タップ効率スコア（0〜1000）
    var efficiency = float(pairs * 2) / float(total_taps) if total_taps > 0 else 0.0
    var efficiency_score = int(efficiency * 1000)

    # 時間ボーナス（制限時間の残り比率 × 500）
    var time_remaining = max(0, time_limit_sec - clear_time_sec)
    var time_bonus = int((time_remaining / time_limit_sec) * 500)

    # 総合スコア
    var raw_score = efficiency_score + time_bonus
    return int(raw_score * tier_multiplier)
```

**例**: T1 で 8 ペア、18 タップ、32 秒でクリア
- 効率 = 16/18 = 0.889 → 889 pts
- 時間ボーナス = (60−32)/60 × 500 = 233 pts
- 合計 = (889 + 233) × 1.0 = **1122 pts**

### 5-2. GDD §6 との差分注記

GDD §6 の原文は `(ペア数 / 総タップ数) × 1000 + 時間ボーナス`。本 spec では **`(ペア数 × 2) / 総タップ数`** を採用する。

| 式 | 完璧プレイ（8ペア/16タップ） | 根拠 |
|---|---|---|
| GDD 原文: `ペア数/タップ数` | 8/16 × 1000 = **500 pts** | 完璧プレイで最大値の半分しか出ない。不自然 |
| 本 spec: `ペア数×2/タップ数` | 16/16 × 1000 = **1000 pts** | 完璧プレイ = 100% = 最大スコア。直感的 |

**GDD §6 の記載は `ペア数` と `ペア数×2（= カード枚数）` の記述ミスと判断**。次回 GDD 更新時に §6 スコア表の神経衰弱行を `(ペア数×2 / 総タップ数) × 1000 + 時間ボーナス` に修正する。

### 5-3. スコアの重み付け方針

| 要素 | 配点割合 | 設計意図 |
|---|---|---|
| タップ効率 | 最大 1000 pts（約 67%） | **記憶の正確性を最重視**。脳トレとしてのコア |

## 8. パラメトリック生成（デイリーシード対応）

### 8-1. シード生成とティアの分離

色文字ストループ spec §8-1 と同じ方針: **共通プール生成 → ティア別フィルタリング**

```gdscript
func generate_daily_cards(seed: int, total_cards: int) -> Array:
    """全ティア共通のカード配置プールを生成。
    total_cards は最大ティアの枚数（T5: 24枚）で生成し、
    小さいグリッドのティアはプールの先頭 N 枚を使う。"""
    var rng = RandomNumberGenerator.new()
    rng.seed = seed

    var max_pairs = total_cards / 2
    var card_ids = []
    for i in range(max_pairs):
        card_ids.append(i)
        card_ids.append(i)

    # Fisher-Yates シャッフル
    for i in range(card_ids.size() - 1, 0, -1):
        var j = rng.randi() % (i + 1)
        var tmp = card_ids[i]
        card_ids[i] = card_ids[j]
        card_ids[j] = tmp

    return card_ids

func get_cards_for_tier(pool: Array, tier: String) -> Array:
    """共通プールからティアに応じた枚数を切り出す"""
    var tier_size = get_tier_card_count(tier)  # T1:16, T4:20, T5:24
    return pool.slice(0, tier_size)
```

### 8-2. カード内容の決定

```gdscript
func get_card_content(card_id: int, tier: String) -> Dictionary:
    match tier:
        "T1", "T4", "T6":
            return SHAPE_CARDS[card_id]  # {shape: "circle", color: "#E53935"}
        "T2":
            return {"number": card_id + 1}
        "T3", "T5":
            return {"number": card_id + 1, "color": COLORS[card_id % 4]}
    return {}
```

### 8-3. 隣接ペアの許容スタンス

Fisher-Yates シャッフルによる完全ランダム配置のため、偶然ペアが隣接配置される可能性がある。

**本 spec のスタンス: 隣接ペアは許容する。フィルタリングしない。**

理由:
- デイリーシードにより**全ユーザーが同じ配置**を体験する。ある日の配置が「簡単」でも全員に等しく簡単なので、公平性は維持される
- GDD §4-5 の改善点「完全ランダム化で公平性担保」の主旨は「特定パターンの繰り返しを排除する」であり、ランダム結果の偏りを禁止するものではない
- 隣接ペア禁止のフィルタリングを入れると、シード→配置の決定論的マッピングが複雑化し、デバッグコストが増大する
- ランダムの結果として「今日は簡単だった/難しかった」のバラつきは、X シェアでの話題性にも貢献する（「今日のデイリー簡単すぎない？」）

### 9-3. 主要スクリプト: memory_match_lite.gd

```gdscript
extends Node
class_name MemoryMatchLite

const MISMATCH_DISPLAY_SEC = 0.5
const MATCH_DISPLAY_SEC = 0.3

var current_tier: String = "T1"
var grid_data: Array = []
var cards: Array = []
var first_card_index: int = -1  # -1 = 未選択
var total_taps: int = 0
var pairs_found: int = 0
var total_pairs: int = 8
var game_start_time_ms: int = 0
var is_processing: bool = false

@onready var ghost_character = $GhostCharacter
@onready var card_grid = $UI/CardGrid

func _ready():
    current_tier = TierManager.get_selected_tier("memory_match_lite")
    var tier_config = get_tier_config(current_tier)
    total_pairs = tier_config.pairs

    var pool = generate_daily_cards(DailySeed.get_today_seed(), 24)
    grid_data = get_cards_for_tier(pool, current_tier)
    setup_grid(tier_config.rows, tier_config.cols)

    ghost_character.set_mode("companion")
    ghost_character.set_dialogue("今日も一緒にカードめくろう。僕も配置覚えるの練習してるよ")
    game_start_time_ms = Time.get_ticks_msec()

func _on_card_tapped(index: int):
    # §2-5 例外処理
    if is_processing:
        return
    if not cards[index].can_tap():
        return  # face_up or matched → 無視、タップカウント加算しない

    total_taps += 1
    cards[index].flip_to_front()
    cards[index].is_face_up = true

    if first_card_index == -1:
        # 1 枚目選択
        first_card_index = index
    else:
        # 2 枚目選択 → ペア判定
        is_processing = true
        var second_index = index
        check_match(first_card_index, second_index)

func check_match(idx1: int, idx2: int):
    if grid_data[idx1] == grid_data[idx2]:
        # ペア成立
        await get_tree().create_timer(MATCH_DISPLAY_SEC).timeout
        cards[idx1].set_matched()
        cards[idx2].set_matched()
        pairs_found += 1

        if current_tier == "T6":
            shuffle_remaining_cards()

        if pairs_found >= total_pairs:
            finish_game(true)
            reset_selection()
            return
    else:
        # 不一致
        await get_tree().create_timer(MISMATCH_DISPLAY_SEC).timeout
        cards[idx1].flip_to_back()
        cards[idx2].flip_to_back()
        cards[idx1].is_face_up = false
        cards[idx2].is_face_up = false

    reset_selection()

func reset_selection():
    first_card_index = -1
    is_processing = false

func finish_game(is_clear: bool):
    var elapsed_sec = (Time.get_ticks_msec() - game_start_time_ms) / 1000.0
    var tier_config = get_tier_config(current_tier)

    var score = calculate_memory_score(
        pairs_found, total_taps, elapsed_sec,
        tier_config.time_limit, tier_config.multiplier)

    GhostData.save_play("memory_match_lite", current_tier, {
        "pairs_found": pairs_found,
        "total_taps": total_taps,
        "clear_time_sec": elapsed_sec,
        "score": score,
        "is_clear": is_clear
    })

    TierManager.check_unlock("memory_match_lite", current_tier,
        pairs_found, total_taps, is_clear)

    ghost_character.set_mode("companion")
    var ghost_score = GhostData.get_average_score("memory_match_lite", current_tier)
    if score > ghost_score:
        ghost_character.set_dialogue("すごい記憶力！ 無駄なタップが全然なかったね")
    elif is_clear:
        ghost_character.set_dialogue("いい勝負だった！ カードの位置、僕もだんだん覚えるのが早くなってきたよ")
    else:
        ghost_character.set_dialogue("ここまでよく頑張ったね。次はもう少し速くいけるよ")

    emit_signal("game_finished", score, pairs_found, total_taps, elapsed_sec)
```

### 9-4. 計測精度の注意点

- カードめくりアニメーション中はタップを無効化（`is_processing` フラグ）
- クリアタイムは `Time.get_ticks_msec()` でフレーム非依存に計測
- 不一致カードの裏返し待機（0.5 秒）はゲーム体験のために厳密に守る
- 制限時間の管理は Timer ノードで行い、`_process` の delta 累積は使わない

## 11. 計測の妥当性

### 11-1. 記憶力の計測

| 指標 | 計算方法 | 用途 |
|---|---|---|
| **タップ効率** | (ペア数 × 2) / 総タップ数 | スコアのメイン指標 |
| **クリアタイム** | ゲーム開始〜全ペア成立 | 時間ボーナス + 詳細表示 |
| **ミスパターン** | どの位置を間違えたか | v1.2 以降の分析用 |

### 11-2. 脳年齢への変換

- タップ効率 95%+ かつ 25 秒以下 = 若年（20 代相当）
- タップ効率 80%+ かつ 40 秒以下 = 標準（30〜40 代）
- タップ効率 70% 未満 or 50 秒超 = シニア（50 代以上）
