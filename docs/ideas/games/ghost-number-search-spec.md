## 1. 概要

### 1-1. コンセプト

**「散らばる数字を、目で捕まえろ。視覚走査の速さを競う数字さがし」**

1〜N の数字がグリッドにランダム配置され、1 から昇順にタップしていく。クリアタイムがスコアに直結するシンプルなゲームだが、認知心理学では**シュルテテーブル**として確立されたパラダイムであり、選択的注意力・周辺視野・視覚走査速度を測定する標準的なツール。

### 1-1b. ゲーム名と命名体系

- 本ゲームは**クリア系**（プレイ中ゴースト非表示、結果画面で比較）
- 日本語名体系を採用: **「数字さがし」**
- GDD §4-6 の原題をそのまま使用。「シュルテテーブル」は学術用語すぎるため、カジュアルな名称を維持

### 1-2. 核のメカニクス

```
[グリッド表示]  →  [次の数字を探す]  →  [タップ]  →  [正誤判定]  →  [繰り返し]
  即時             視覚走査           選択        即時          1〜N まで
```

1. グリッドに 1〜N の数字がランダム配置される
2. プレイヤーは 1 から昇順に数字を探してタップ
3. 正しい数字をタップすると次の数字が対象になる。間違った数字をタップすると何も起きない（ペナルティなし、ミスタップ数のみカウント）
4. N までタップし終えるまでのクリアタイムで評価

### 1-3. 差別化ポイント（競合類型との比較）

| 類型 | 代表例 | 問題点 | 本作の改善 |
|---|---|---|---|
| A. 標準シュルテテーブル | Schulte Table 各種 / Focusaur | 速読訓練が主目的。ゲーム性が薄い | **ゴースト対戦 + ティア段階制**で脳トレゲームに昇華 |
| B. 脳トレ統合型 | みんなの脳トレ「観察力」 | 5×5 固定で飽きやすい。説明不足 | **ティア進行**（3×3→5×5→視覚干渉）で段階的に挑戦 |
| C. 数字さがし専用アプリ | 脳トレ！数字さがし (jaykeigames) | 「広告が多く割込み集中力を妨げる」（GDD 付録 B） | GDD §7 広告設計準拠。プレイ中広告ゼロ |
| D. 高機能シュルテ | Schulte Arena | 機能が多すぎて脳トレ初心者に不向き。有料 $2.99 | MVP は 5×5 のみ。シンプルに始めてティアで深みを出す |
| E. 数字配置固定 | 一部のシュルテアプリ | 配置を覚えると成績が向上し、測定精度が低下 | **デイリーシード**で毎日配置が変わる |

### 1-4. シュルテテーブルの学術的背景と本作のスタンス

シュルテテーブルは 1920 年代にドイツの精神科医 Walter Schulte が考案。元々は航空パイロットの視覚走査能力測定に使われ、現在は速読訓練・注意力測定・認知リハビリに広く応用されている。

本作では:
- **エンターテインメント目的**であることを明示（GDD §13 準拠）
- 「周辺視野を使って目を中央に固定する」というシュルテ本来の訓練法は**強制しない**（スマホ画面サイズでは周辺視野訓練の効果が限定的）
- ただし、T5 以降でグリッド中央に固定点を表示し、「目を動かさず探す」モードをオプション提供（v1.1 検討）

## 2. ゲームルール

### 2-1. 全体の流れ

```
┌─ クリアまでの流れ ─────────────────┐
│ 1. グリッド（ティアで決定）表示    │
│ 2. 現在の対象数字を探す            │
│ 3. タップ                          │
│    ├ 正解 → 数字がハイライト、    │
│    │        次の数字が対象に       │
│    └ 不正解 → 何も起きない        │
│ 4. N まで繰り返し                 │
└───────────────────────────────────┘
  ↓
結果表示（クリアタイム・ゴースト比較）
```

### 2-2. グリッドの仕様

| ティア | グリッド | 数字範囲 | 数字の見た目 | 制限時間 |
|---|---|---|---|---|
| T1 | 3×3 | 1〜9 | 統一サイズ・白文字 | 30 秒 |
| T2 | 4×4 | 1〜16 | 統一サイズ・白文字 | 45 秒 |
| T3 | 5×5 | 1〜25 | 統一サイズ・白文字 | 60 秒 |
| T4 | 5×5 | 1〜25 | **サイズ可変**（後述） | 60 秒 |
| T5 | 5×5 | 1〜25 | **サイズ + 色可変** | 60 秒 |
| T6 | 5×5 | 1〜25 | サイズ + 色可変 + **回転** | 60 秒 |

**制限時間キャップ: 60 秒**（神経衰弱ライト spec と同じ原則）

### 2-3. 数字の視覚表現

GDD §4-6 の「数字の位置・フォントサイズ・色をランダム化」を、ティアごとの視覚干渉として体系化:

**T1〜T3（統一表示）**: 全数字が同じサイズ（24sp）・同じ色（白）・同じ角度（0°）で表示。純粋な視覚走査速度を測定。

**T4（サイズ可変）**: 各数字のフォントサイズが 16sp〜32sp でランダム。小さい数字は見つけにくく、大きい数字は目を引いて干渉する。

**T5（サイズ + 色可変）**: サイズ可変に加え、数字の色が 4 色（白・シアン・オレンジ・薄紫）からランダム。色の目立ちやすさに差があり、視覚的な「罠」が生まれる。

**T6（サイズ + 色 + 回転）**: 各数字が −30°〜+30° でランダム回転。Schulte Arena の "rotate" モードから着想。

**6/9 区別の方針（T6）**: 回転により 6 が 9 に、9 が 6 に見える角度が存在する。これは**意図的な視覚干渉として許容する**。理由:
- 「曖昧な視覚情報から正しい数字を判断する」こと自体が T6 の追加課題
- 文脈（昇順タップなので「次は 6 か 9 か」はゲーム進行から推測可能）で解決できる
- 「6/9 問題」は付録 C の議論候補にも記載。v1.1 で下線マーカー（6̲）の追加を A/B テスト予定

### 2-4. タップ判定

| 判定 | 条件 | 挙動 |
|---|---|---|
| **正解** | 現在の対象数字をタップ | 数字が緑にハイライト → 次の対象に進む |
| **不正解** | 対象以外の数字をタップ | 何も起きない。ミスタップ数をカウント |
| **空白タップ** | 数字以外の領域をタップ | 無視 |
| **既タップ数字** | すでにクリア済みの数字をタップ | 無視 |

**不正解にペナルティを与えない理由**:
- スコア式は「残り時間比率」（§5）のため、不正解タップは時間消費で自然にペナルティが発生
- 明示的なペナルティ（赤フラッシュ・時間追加等）は GDD §6 の赤禁止ルールと UX 設計思想に反する
- ミスタップ数は記録する（結果画面の詳細エリアに表示）

### 2-5. 現在の対象数字の表示

プレイ中、画面上部に「次に探す数字」を常時表示:

```
┌─ 上部 HUD ────────────┐
│  次: 14    ⏱ 18秒     │
└────────────────────────┘
```

- 「次: 14」が大きく白で表示（24sp）
- グリッド内の数字を探す際の参照点
- 対象数字をタップするたびに自動更新

## 4. ティア段階制

GDD §5b 準拠。

### 4-1. ティア体系

| ティア | グリッド | 数字範囲 | 視覚干渉 | 制限時間 | 難度倍率 |
|---|---|---|---|---|---|
| **T1** | 3×3 | 1〜9 | なし | 30 秒 | ×1.0 |
| **T2** | 4×4 | 1〜16 | なし | 45 秒 | ×1.0 |
| **T3** | 5×5 | 1〜25 | なし | 60 秒 | ×1.0 |
| **T4** | 5×5 | 1〜25 | サイズ可変 | 60 秒 | ×1.3 |
| **T5** | 5×5 | 1〜25 | サイズ + 色可変 | 60 秒 | ×1.6 |
| **T6** | 5×5 | 1〜25 | サイズ + 色 + 回転 | 60 秒 | ×2.0 |

**v1.0 → v1.1 変更点**: T1〜T3 の難度倍率を全て ×1.0 に統一。理由は §5 のスコア式変更でティアごとの制限時間が自動的に難度差を生むため（後述）。T4〜T6 の倍率も圧縮（旧 ×1.8/2.2/2.8 → ×1.3/1.6/2.0）して、視覚干渉ティアにのみ加点する設計に。

### 4-2. 視覚干渉の設計思想

```
T1-T3: グリッド拡張で「探す対象が増える」（量的難度UP）
       → 制限時間も拡張するため、スコア式で自動均衡（§5 参照）
T4-T6: 視覚干渉で「見つけにくくなる」（質的難度UP）
       → 難度倍率で追加加点
```

### 4-3. 解放条件

```
解放条件: 現在ティアで直近 5 回中 3 回クリア
```

- クリア = 制限時間内に全数字をタップ完了
- タイムの閾値は設けない（クリアできること自体が十分な実力証明）
- T1 は初回から解放。各ティア独立のゴーストデータを保持。再ロックしない

## 5. スコア算出

### 5-1. スコア計算式（v1.1 改訂）

**残り時間比率ベース**に変更。ティアのグリッドサイズ・制限時間が異なっても均衡するスコア式。

```gdscript
const BASE_SCORE = 1500

func calculate_search_score(clear_time_sec: float, time_limit_sec: float,
    tier_multiplier: float) -> int:
    if clear_time_sec >= time_limit_sec:
        return 0  # タイムアウト

    var remaining_ratio = (time_limit_sec - clear_time_sec) / time_limit_sec
    var raw = int(BASE_SCORE * remaining_ratio)
    return int(raw * tier_multiplier)
```

**スコアの振る舞い**:

| ティア | 制限時間 | 半分でクリア | 残り5秒でクリア | ティア倍率 | 半分クリア時スコア |
|---|---|---|---|---|---|
| T1 | 30 秒 | 15 秒 | 25 秒 | ×1.0 | 750 |
| T2 | 45 秒 | 22.5 秒 | 40 秒 | ×1.0 | 750 |
| T3 | 60 秒 | 30 秒 | 55 秒 | ×1.0 | 750 |
| T4 | 60 秒 | 30 秒 | 55 秒 | ×1.3 | 975 |
| T5 | 60 秒 | 30 秒 | 55 秒 | ×1.6 | 1200 |
| T6 | 60 秒 | 30 秒 | 55 秒 | ×2.0 | 1500 |

→ **どのティアでも「制限時間の半分でクリア」= 750 pts（T1〜T3）**。均衡が取れている。T4 以降は視覚干渉の追加難度を倍率で加点。

### 5-2. GDD §6 との差分注記

GDD §6 の原文は `max(0, 3000 − クリア秒数×100)`。本 spec では**残り時間比率ベースの式**に変更する。

| 式 | T1(8秒) | T3(24秒) | T3(35秒) | 問題点 |
|---|---|---|---|---|
| GDD 原文 | 2200 pts | 600 pts | 0 pts | T3で30秒超=0pts。平均的成人の半数がスコア0 |
| 本 spec | 1100 pts | 900 pts | 625 pts | 全ティアで均衡。30秒超でもスコアが出る |

**GDD §6 の式は 5×5 グリッドのみを前提とした初期設計**と判断。ティア制（3×3〜5×5）の導入に伴い、残り時間比率ベースに改訂。次回 GDD 更新時に §6 スコア表の数字さがし行を修正する。

### 5-3. タイムアウト

制限時間内にクリアできなかった場合:
- スコア = 0 pts
- ティア解放条件にカウントされない
- 結果画面に「タイムアウト N/25 見つけた」と表示（到達した数字を記録）

## 6. ゴースト対戦との接続（§5b）

### 6-1. 比較対象と勝敗判定

**内部判定はスコア、画面表示はクリアタイム**（§3-3 参照）。

```
プレイ中: ゴースト非表示（GDD §5b クリア系ルール）
結果画面: 「いつもの自分: 28秒 → 今日: 24秒 🎉勝利！」
内部判定: ghost_score(600) < player_score(900) → 勝利
```

### 6-2. ゴーストデータ構造

```python
ghost_data = {
    "game": "number_search",
    "tier": "T3",
    "last_5_plays": [
        {
            "date": "2026-05-19",
            "clear_time_sec": 28.5,
            "score": 788,
            "is_clear": true,
            "miss_taps": 3
        },
    ]
}
ghost_score = sum(p["score"] for p in last_5 if p["is_clear"]) / max(1, len([p for p in last_5 if p["is_clear"]]))
```

**未クリア回のスコア（0 pts）をゴースト平均に含めるか**: 含めない。未クリアは「計測不能」であり、平均を引き下げるのは不公平。クリア回のみで平均を算出。

| T1 | 15 秒 | 750 pts | 3×3 平均的成人で 12〜18 秒 |
| T2 | 28 秒 | 567 pts | 4×4 でやや増加 |
| T3 | 35 秒 | 625 pts | 5×5 標準。研究データ平均 25〜35 秒 |

## 8. パラメトリック生成（デイリーシード対応）

### 8-1. ティアごとの独立シャッフル

**設計原則: 各ティアの数字範囲（T1:1〜9, T2:1〜16, T3+:1〜25）を独立にシャッフルする。シードは日付ベースで共通だが、ティアごとにオフセットを加える。**

v1.0 の「25 マス生成して先頭 N 個を取る」方式は、T1 で 1〜25 の数字が出現するバグがあった（C2）。

```gdscript
func generate_daily_grid(seed: int, tier: String) -> Array:
    """ティアに応じた数字範囲で独立にシャッフル"""
    var tier_offset = {"T1": 0, "T2": 100, "T3": 200,
                       "T4": 200, "T5": 200, "T6": 200}
    var rng = RandomNumberGenerator.new()
    rng.seed = seed + tier_offset[tier]

    var max_num = get_tier_max_number(tier)  # T1:9, T2:16, T3+:25
    var numbers = []
    for i in range(1, max_num + 1):
        numbers.append(i)

    # Fisher-Yates シャッフル
    for i in range(numbers.size() - 1, 0, -1):
        var j = rng.randi() % (i + 1)
        var tmp = numbers[i]
        numbers[i] = numbers[j]
        numbers[j] = tmp

    return numbers
```

**ティア間の Wordle 公平性**: 同じティアでプレイするユーザーは同じ配置を体験する（シード + ティアオフセットが同一）。異なるティア間では配置が異なるが、これは意図的（ティアが違えば体験も異なって当然）。

### 8-2. 視覚干渉パラメータの生成（T4+）

```gdscript
func generate_visual_modifiers(seed: int, tier: String) -> Array:
    var rng = RandomNumberGenerator.new()
    rng.seed = seed + 500  # グリッド配置とは異なるシードオフセット

    var modifiers = []
    var max_num = get_tier_max_number(tier)
    for i in range(max_num):
        var mod = {"size": 24, "color": "white", "rotation": 0}

        if tier in ["T4", "T5", "T6"]:
            mod.size = rng.randi_range(16, 32)
        if tier in ["T5", "T6"]:
            mod.color = ["white", "cyan", "orange", "light_purple"][rng.randi() % 4]
        if tier == "T6":
            mod.rotation = rng.randi_range(-30, 30)

        modifiers.append(mod)
    return modifiers
```

### 8-3. 隣接配置のスタンス

神経衰弱ライト spec §8-3 と同じ: **純粋ランダム許容**。連番が隣接する「簡単な」配置もデイリーシードで全員共通なので公平。

### 9-2. 主要スクリプト: number_search.gd

```gdscript
extends Node
class_name NumberSearch

var current_tier: String = "T3"
var grid_data: Array = []
var cells: Array = []
var current_target: int = 1
var total_taps: int = 0
var miss_taps: int = 0
var game_start_time_ms: int = 0
var max_number: int = 25

@onready var ghost_character = $GhostCharacter
@onready var next_number_label = $UI/HUD/NextNumber

func _ready():
    current_tier = TierManager.get_selected_tier("number_search")
    var tier_config = get_tier_config(current_tier)
    max_number = tier_config.max_number

    grid_data = generate_daily_grid(DailySeed.get_today_seed(), current_tier)
    var modifiers = generate_visual_modifiers(DailySeed.get_today_seed(), current_tier)

    setup_grid(tier_config.rows, tier_config.cols, modifiers)
    update_hud()

    ghost_character.set_mode("companion")
    ghost_character.set_dialogue("今日も一緒に数字を探そう。僕も目が速くなってきたよ")
    game_start_time_ms = Time.get_ticks_msec()

func _on_cell_tapped(cell_index: int):
    var cell = cells[cell_index]
    if cell.is_found:
        return

    total_taps += 1

    if cell.number == current_target:
        cell.mark_found()
        current_target += 1
        update_hud()
        if current_target > max_number:
            finish_game(true)
    else:
        miss_taps += 1

func finish_game(is_clear: bool):
    var elapsed_sec = (Time.get_ticks_msec() - game_start_time_ms) / 1000.0
    var tier_config = get_tier_config(current_tier)

    var score = calculate_search_score(
        elapsed_sec, tier_config.time_limit, tier_config.multiplier)

    GhostData.save_play("number_search", current_tier, {
        "clear_time_sec": elapsed_sec,
        "score": score,
        "is_clear": is_clear,
        "miss_taps": miss_taps,
        "reached_number": current_target - 1
    })

    TierManager.check_unlock("number_search", current_tier, is_clear)

    ghost_character.set_mode("companion")
    var ghost_data = GhostData.get_average("number_search", current_tier)
    if is_clear and score > ghost_data.score:
        ghost_character.set_dialogue("すごい観察力！ 数字がどこにあるかすぐ見つけるんだね")
    elif is_clear:
        ghost_character.set_dialogue("いい勝負だった！ 僕も少しずつ速くなってるよ")
    else:
        ghost_character.set_dialogue("ここまでよく頑張ったね。次はきっとクリアできるよ")

    emit_signal("game_finished", score, elapsed_sec, is_clear)

func update_hud():
    next_number_label.text = "次: %d" % current_target
```

### 9-3. 計測精度の注意点

- クリアタイムは `Time.get_ticks_msec()` でフレーム非依存に計測
- 最後の数字タップ時に即座にタイマー停止。フィードバックアニメーション前にタイム確定
- 数字さがしの精度要件は 100ms 単位。フレームレート影響は無視可能

**初回フロー時のティア扱い**:

- v1.1 で T1（3×3）を追加した後は、初回フローを T1 で実施するよう変更

## 11. 計測の妥当性

### 11-1. 観察力の計測

| 指標 | 計算方法 | 用途 |
|---|---|---|
| **クリアタイム** | ゲーム開始〜最後の数字タップ | スコアのメイン指標 + 結果画面の主役 |
| **ミスタップ数** | 不正解タップの回数 | 詳細表示 |
| **正確率** | max_number / (max_number + miss_taps) | 詳細表示 |

### 11-2. 脳年齢への変換

T3（5×5）のクリアタイムで換算:
- 20 秒未満 = 若年（20 代相当）
- 20〜30 秒 = 標準（30〜40 代）
- 30 秒超 = シニア（50 代以上）

参考: シュルテテーブルの研究データでは、健常成人の平均は約 25〜35 秒。

## 12. UX 細部

### 12-1. 初回オンボーディング

```
画面 1: "数字さがし"
       → "1 から順番に数字を見つけてタップ！"
画面 2: [3×3 の小さなグリッドで 1→2→3 をタップするアニメ]
       → "見つけたらすぐタップ。速さがスコアだよ"
画面 3: [練習: 3×3 で 1〜9]
       → "練習成功！ 本番は 5×5 だよ"
画面 4: [カウントダウン] → "3...2...1... スタート！"
```

**初回フローの練習ラウンドは 3×3**（MVP に T1 がなくても、オンボーディング内の練習は 3×3 で実施。本番は T3 の 5×5 に移行）

### 12-2. 音響設計

| 音 | タイミング | 長さ | 備考 |
|---|---|---|---|
| 正解タップ音 | 正しい数字タップ時 | 0.05 秒 | ポッ（非常に短い。テンポ重視） |
| クリア音 | 最後の数字タップ時 | 0.5 秒 | ファンファーレ |
| タイマー警告 | 残り 10 秒 | 0.3 秒 | ティッティッ |

BGM なし。GDD §9 に従い個別オンオフ可能。

### 12-3. アクセシビリティ

- 数字は言語非依存（アラビア数字）。GDD §4 準拠
- フォント: T3 以下は 24sp 統一。T4 以降の最小は 16sp（GDD §9 の最低 14sp を上回る）
- セルサイズ: 最小 56dp（タップ領域として十分）
- 色覚配慮: T5 の色可変で使う 4 色は全て明度が異なり、色覚異常でも区別可能
