# ユースケース別ガイド

相談のカテゴリに応じた、ヒアリング項目・リサーチ項目・回答テンプレートの詳細ガイド。

---

## 技術選定（ORM、フレームワーク、インフラ等）

**ヒアリングで必ず確認する項目:**
- 対象言語・フレームワーク
- デプロイ先の制約（Cloudflare Workers / AWS Lambda / VPS等）
- 既存技術スタックとの整合性
- チーム規模と学習コストの許容度

**リサーチで必ず調べる項目:**
- 各候補の最新バージョンとリリース日
- 公式ドキュメントの充実度
- GitHubスター数・最終コミット日・Issue対応状況
- 破壊的変更の履歴
- Cloudflare Workers / Edge Runtime対応状況（該当する場合）
- npm weeklyダウンロード数の推移

**回答テンプレート:**
```
## 結論: [推奨ツール名]

[2〜3文で推奨理由を述べる]

## 比較表

| 項目 | 選択肢A | 選択肢B | 選択肢C |
|------|---------|---------|---------|
| 最新バージョン | | | |
| 型安全性 | | | |
| Edge対応 | | | |
| 日本語ドキュメント | | | |
| 学習コスト | | | |
| エコシステム | | | |

## 詳細分析
[各選択肢の強み・弱みをソース付きで]

## この選定で注意すべき点
[トレードオフ、将来的なリスク]

## 次のステップ
[具体的な導入手順]
```

## SaaS/サービス比較（決済、ホスティング、SaaS等）

**ヒアリングで必ず確認する項目:**
- ビジネスモデル（BtoB / BtoC / CtoC）
- 想定取引量・金額帯
- 対象地域（日本のみ / グローバル）
- 法人 / 個人事業主

**リサーチで必ず調べる項目:**
- 最新の料金体系（日本円での実質コスト）
- 日本での法的対応（特定商取引法、資金決済法等）
- 日本語サポートの有無と質
- 日本での導入事例
- API/SDKの品質とドキュメント
- 解約・移行の容易さ（ロックイン度）

**回答テンプレート:**
```
## 結論: [推奨サービス名]

[2〜3文で推奨理由を述べる]

## コスト比較（月間[想定取引量]の場合）

| 項目 | サービスA | サービスB |
|------|-----------|-----------|
| 基本料金 | | |
| 決済手数料 | | |
| 月額100件の実質コスト | | |
| 月額1000件の実質コスト | | |

## 機能比較
[サブスクリプション、Webhook、管理画面等]

## 日本での運用面
[法的対応、サポート、ドキュメント]

## リスクと注意点
[ロックイン、為替リスク、障害履歴等]
```

## 社内提案・企画の相談

**ヒアリングで必ず確認する項目:**
- 提案先（経営層、部門長、チーム等）
- 期待される成果とKPI
- 予算・リソースの制約
- 組織内の政治的配慮事項
- 既存の取り組みとの関係

**リサーチで調べる項目:**
- 同業他社の類似取り組み事例
- ベンダー/ツールの最新情報
- ROI試算に使えるデータ
- 業界レポート・ガイドライン

**回答テンプレート:**
```
## 提案の切り口

### 推奨アプローチ: [提案名]
[2〜3文で概要]

### なぜ今なのか（外部環境）
- [市場動向・競合動向のデータ]
- [技術成熟度の根拠]

### 期待効果
- 定量: [具体的な数値目標と算出根拠]
- 定性: [組織的なメリット]

### 想定コスト
- 初期: [内訳]
- ランニング: [月額/年額]

### リスクと対策
- [リスク1] → [対策]
- [リスク2] → [対策]

### ロードマップ案
- Phase 0 (〜X月): [内容]
- Phase 1 (〜Y月): [内容]
```

## 法務・税務・行政手続きの相談

**必ず付加する注意事項:**
> 「以下は調査結果に基づく情報提供であり、法的助言ではありません。実際の手続きについては税理士・行政書士等の専門家にご確認ください。」

**ヒアリングで必ず確認する項目:**
- 法人 / 個人事業主
- 所在地（管轄税務署・自治体）
- 現在のステータス（開業済み / これから等）
- 関連する制度（青色申告、インボイス等）

**リサーチで調べる項目:**
- 最新の法令・通達
- 国税庁・自治体の公式FAQ
- 制度の最新改正情報
- 対象となる届出書類の最新様式

---

## Micro SaaS / 個人開発プロダクトの相談

**ヒアリングで必ず確認する項目:**
- ターゲットユーザ（誰の何の課題を解決するか）
- 競合・類似サービスの認識
- マネタイズモデル（サブスク / 買い切り / フリーミアム）
- MVP時点の最小スコープ
- 使用する技術スタック

**リサーチで調べる項目:**
- 競合サービスの最新状況（料金、機能、ユーザ数）
- ターゲット市場の規模感（TAM/SAM/SOM的な概算）
- 類似プロダクトのProduct Hunt・Indie Hackers事例
- 技術的な実現可能性（API制限、利用規約等）

**回答テンプレート:**
```
## 評価サマリー

### 市場機会
- ターゲット: [具体的なペルソナ]
- 市場規模感: [データに基づく概算]
- 競合状況: [主要競合と差別化ポイント]

### 技術面
- 実現可能性: [高/中/低] — 理由: [具体的根拠]
- 推奨技術スタック: [ソース付きで]

### ビジネス面
- 想定MRR到達シナリオ: [保守的/楽観的]
- 初期コスト: [インフラ、ドメイン、決済等]
- 参考事例: [類似プロダクトの実績]

### Go/NoGo判定材料
- Go要因: [箇条書き]
- リスク要因: [箇条書き]
- 推奨: [判断と根拠]
```
